## 0. 全链路总览

### 0.1 IVPT 在做什么（一分钟心智模型）

IVPT 想要一个**既能分类、又能解释「看了哪些部位」**的模型。做法是：拿一个**预训练好的 DINOv2 ViT-Base**
当主干（本次**冻结**，几乎不训练），在它**最后 4 个 Transformer block** 里插入一组可学习的「**原型(prototype)**」，
让这些原型去「认领」图像里的不同区域，从而无监督地发现 **4 个前景部件(landmark) + 1 个背景**。

一张图进来后的大致旅程：

1. 切成 patch 过 ViT（本次 `518×518`、patch14 → 得到 `37×37` 的 patch 特征网格）。
2. 在最后 4 个 block，每层注入一批原型：原型与每个 patch 算距离 → softmax 得到「每个 patch 属于哪个原型」的图；
   再用一个分类头 + **Gumbel-Softmax** 把这些原型**软分配/归并**到 4 个部件上。
3. 把每个部件聚合出的特征拼回 token 序列继续过 block，最后对各部件特征分类。
4. 训练时除了分类损失，还有 **7 个辅助损失**约束这些部件「长得合理」（该出现、平滑、互不重叠、几何稳定、背景占边缘……）。

> 一句话：**冻结的 ViT 负责看，少量新增的「部件发现层」负责把注意力组织成可解释的部件，再拿部件特征分类。**

### 0.2 端到端调用序列

下面是从命令行一路调到训练循环的主干（`文件::函数`）。括号里是本次的实际行为。

```
scripts/run_train.sh
  └─ torchrun ... train_net.py            # 单卡 1 进程
     └─ train_net.py :: ivpt_train_eval()
        ├─ argument_parser_train.parse_args()        # 解析所有 --xxx
        ├─ wandb_params.get_train_loggers()          # 没开 --wandb → 返回 []
        ├─ misc_utils.check_snapshot()               # 建 ./snapshot 目录
        ├─ transform_utils.load_transforms()         # cub_original：强训练增强 + 弱测试增强
        ├─ data_sets.builder.get_dataset()           # CUB 训练集/测试集, num_cls=200
        │     └─ fg_bird_dataset.FineGrainedBirdClassificationDataset
        ├─ models.builder.load_model_ivpt()          # DINOv2 ViT-B(冻结) + 部件发现层
        │     ├─ load_model_arch()                   # timm create_model
        │     └─ init_ivpt_model() → IndividualLandmarkViT
        ├─ ddp_utils.multi_gpu_check()               # 单卡 → False（跳过 SyncBN/DDP）
        ├─ losses.builder.load_classification_loss() # 普通 CrossEntropy, mixup=None
        ├─ losses.builder.load_loss_hyper_params()   # 各辅助损失权重 + 等变仿射范围
        ├─ optimizer_params.layer_group_matcher_ivpt()  # 5 组分组学习率
        ├─ optimizer_params.build_optimizer()        # Adam
        ├─ scheduler_params.build_scheduler()        # StepLR(γ=0.5, step=4)
        └─ distributed_trainer_ivpt.launch_ivpt_trainer()
              ├─ ddp_utils.set_seeds()
              ├─ PDiscoTrainer.__init__()            # 3 个 DataLoader + 损失/指标/可视化器
              └─ PDiscoTrainer.train()               # ↓ 训练循环
```

训练循环（`PDiscoTrainer.train`，epoch 1..25）：

```
for epoch in 1..25:
  model.train()
  _run_epoch(train=True):
     for each batch:
        _run_batch(train=True):
           ① forward(source)                         # 见 0.1 第 1~3 步，individual_landmark_vit.forward
           ② 采随机仿射 → 变换图 → 再 forward 一次     # 给等变损失用
           ③ 算 8 个损失并相加                         # 分类/一致性/全变差/presence/正交/等变/enforced/像素熵
           ④ 反向 → 梯度裁剪(范数≤2.0) → optimizer.step()
  每 10 epoch 存检查点；每 5 epoch 用 10% 测试集评估一次(刷新最高就存 best)
训练结束：在全量测试集上做最终评估
```

## 1. 启动与总调度

> **读这些**：`scripts/run_train.sh` → `train_net.py::ivpt_train_eval` → `argument_parser_train.py::parse_args`

这一章是整条流程的「骨架」：搞清楚**敲下 `bash scripts/run_train.sh` 之后，到底按什么顺序把零件备齐**。
这三个文件本身**都不做训练计算**——一个负责拼参数、一个负责按序调用、一个负责登记参数。

### 1.1 run_train.sh —— 启动器

**角色**：把一堆超参数整理成命令行参数，再用 `torchrun` 把它们喂给 `train_net.py`。它就是个「参数清单 + 启动命令」。

**怎么读**：文件分几段——路径 / 分布式 / 训练 / 优化器调度器 / 损失权重 / 模型——每段定义一批 shell 变量，
最后一个 `torchrun ... \` 把所有变量拼成 `--xxx` 传给 `train_net.py`。

**要注意的点**：

- **作者的改动**：脚本里有成对的 `# XXX=...`（注释掉的原版）和紧跟其后生效的那行。当前是**单卡**配置：
  `NUM_GPUS=1`（原版 4）、`BATCH_SIZE=12`（原版 4）。
- **学习率的平方根缩放**：`LR=0.866e-6`。论文基准是 batch 16 → `1e-6`；按平方根缩放规则换到 batch 12：
  `1e-6 × √(12/16) ≈ 0.866e-6`。这是作者算好填进去的，不是代码自动缩放。
- **⚠ 一个 bash 坑**：`torchrun` 那条用 `\` 续行的长命令**中间不能插注释**——`\` 后面必须紧跟换行，
  否则会把命令截断。所以那些**直接写死、不来自变量**的 flag 的含义，集中写在了 `torchrun` 上方的块注释里：
  `--pretrained_start_weights`（主干加载预训练权重）、`--train_split 1`（用全部训练集、不切 val）、
  `--eval_mode test`、`--gumbel_softmax`、`--freeze_backbone`、`--augmentations_to_use cub_original`、
  `--drop_path 0.0`、`--smoothing 0`。

### 1.2 train_net.py —— 总调度（13 步）

**角色**：`ivpt_train_eval()` 是真正的程序入口（`torchrun` 最终执行到这里）。它**只做编排**：按顺序把各零件准备好，
最后一次性交给训练器 `launch_ivpt_trainer()`。它自己不写任何前向/反向。

**13 步编排**（每步在本次配置下的实际行为）：

| 步 | 调用 | 本次实际发生 |
|---|---|---|
| 1 | `parse_args()` | 解析 `run_train.sh` 传来的所有 `--xxx` |
| 2 | `get_train_loggers()` | 没开 `--wandb` → 返回 `[]`（不记 wandb） |
| 3 | `check_snapshot()` | 建好 `./snapshot` 目录 |
| 4 | `load_transforms()` | `cub_original`：训练强增强 + 测试弱增强 |
| 5 | `get_dataset()` | CUB 训练/测试集，`num_cls=200` |
| 6 | `load_model_ivpt()` | 冻结的 DINOv2 ViT-B + 部件发现层 |
| 7 | `multi_gpu_check()` | 单卡 → `False`；`sync_bn_conversion` 跳过 |
| 8 | `load_classification_loss()` | 普通 `CrossEntropyLoss`，`mixup_fn=None` |
| 9 | `load_loss_hyper_params()` | 各辅助损失权重 + 等变仿射范围 |
| 10 | `layer_group_matcher_ivpt` → `build_optimizer` → `build_scheduler` | 5 组分组学习率 → Adam → StepLR |
| 11 | `timer()` | 开始计时 |
| 12 | `launch_ivpt_trainer(...)` | **正式开训**（训练循环/评估/存档全在里面） |
| 13 | `timer()` + print | 打印总耗时 |

> 读到这里，你已经看清了"骨架"：第 4~10 步备好的零件，分别对应本文档第 2~6 章；第 12 步进入的训练循环是第 7、8 章。

### 1.3 argument_parser_train.py —— 配置源

**角色**：用 `argparse` 把所有 `--xxx` 登记下来，解析成 `args` 返回。`run_train.sh` 里的每个 flag 都得先在这里登记过才认。

**怎么读（重点）**：参数有上百个，但本次真正传了的只是一部分。注释里给了导航：

- 凡带 **【本次】** 标记的，就是这次训练实际用到 / 被命令行覆盖了的；其余多是别的数据集 / 消融实验 / 默认关闭的功能。
- `default=` 是「命令行不传时的默认值」；命令行传了就以命令行为准。
- `action='store_true'` 是开关：命令行写了就 `True`，不写就 `False`。

**几个 default 与本次实际值不一样、容易看错的**：

| 参数 | default | 本次值 | 说明 |
|---|---|---|---|
| `--train_split` | `0.9` | `1` | 用全部训练集、不切验证集 |
| `--eval_mode` | `val` | `test` | 在测试集上评估 |
| `--image_size` | `448` | `518` | DINOv2 默认分辨率 |
| `--scheduler_type` | `cosine` | `steplr` | |
| `--enforced_presence_loss` | `2.0` | `1` | 权重被命令行覆盖 |

**本次用不到、属于"摆设"的几组**（代码里也标了）：mixup/cutmix、random erase、imbalanced TopK、
以及只在 `timm` 增强分支才读的 `color_jitter/aa/reprob`。还有一个 `--concentration_loss`：它会被打包进损失超参字典，
但**训练器代码里根本没读它**（详见第 4、6 章）。

## 2. 数据管线

> **读这些**：`transform_utils.py::load_transforms` → `data_sets/builder.py::get_dataset` → `fg_bird_dataset.py::FineGrainedBirdClassificationDataset`（`__init__` + `__getitem__`）→ `dataset_utils.py::pil_loader`

这一章对应 `train_net.py` 的第 4、5 步。数据这条线的流向很简单：
**先定义"怎么增强"(transforms) → 再建数据集(把 transforms 塞进去) → 训练时 DataLoader 逐张调 `__getitem__`：读图 → 增强 → 吐出 `(图, 标签)`**。

形状流向：一张原图 → 增强 → `[3, 518, 518]` 张量 → DataLoader 攒成一个 batch `[B, 3, 518, 518]`。

### 2.1 transform_utils.py —— 增强流水线

**角色**：`load_transforms(args)` 是入口，按 `augmentations_to_use` 选用哪套增强，返回 `(训练增强, 测试增强)`。
本次 `cub_original` → 训练走 `make_train_transforms`、测试走 `make_test_transforms`（`timm` 那条 `build_transform_timm` 本次不走）。

**训练增强（强，每张图每个 epoch 重新随机）** `make_train_transforms`：

```
Resize(短边→518) → 随机水平翻转(p=0.5) → 随机垂直翻转(p=0.0) → ColorJitter
→ RandomAffine(旋转±90°, 平移±20%, 缩放0.8~1.2) → RandomCrop(518) → ToTensor → Normalize(ImageNet)
```

- **⚠ 写死的值**：`RandomAffine` 的 `90 / 0.2 / 0.8,1.2` 是**直接写死的、不读 `args`**；`color_jitter/aa/reprob` 这些命令行参数只有 `timm` 分支才读。
- 垂直翻转 `p=0.0` 等于没开；旋转 `±90°` 对细粒度任务算激进（鸟可能被转倒），属经验设置。

**测试增强（弱，确定性）** `make_test_transforms`：`Resize(短边→518) → CenterCrop(518) → ToTensor → Normalize`。
没有随机，保证评估可复现、不裁掉判别性区域。

**反归一化三件套** `inverse_normalize / normalize_only / inverse_normalize_w_resize`：训练**不用**，是后面可视化（第 8 章）把标准化的图还原成正常颜色用的。数学：标准化是 `(x-mean)/std`，反过来需要 `x*std+mean`，于是凑 `mean'=-mean/std、std'=1/std` 代进 `Normalize` 公式即可。

### 2.2 builder.py —— 数据集工厂

**角色**：`get_dataset` 按 `args.dataset` 选数据集类。cub 和 nabirds 共用同一个 `FineGrainedBirdClassificationDataset`。

- 训练集：`mode='train'`、`split=args.train_split`（本次 `1` 即全量）、配训练增强。
- 测试集：`mode=args.eval_mode`（本次 `test`）、配测试增强、不传 split。
- 类别总数 `num_cls` 从训练集取（CUB=200），后面给模型分类头和损失用。

### 2.3 fg_bird_dataset.py —— 数据集本体

**角色**：把 CUB 的几个标注 txt 读成一张表，`__getitem__` 按下标吐出 `(增强后的图, 标签)`。

**`__init__` 做的事**：

1. 读 4 个空格分隔的 txt 并 `merge` 成一张大表：
   `train_test_split.txt`（图id, 是否训练集）、`images.txt`（图id, 文件名）、`image_class_labels.txt`（图id, 标签）、`parts/part_locs.txt`（图id, 部件id, x, y, 是否可见）。
2. **按 `mode` 切分**：`train`=官方训练集前 `split` 比例；`test`=官方测试集（`train==0`）；`val`=训练集后 `(1-split)`。
   **⚠ 坑**：`split=1` 时 `val` 会切出**空集**——本次用 train+test 不受影响，但要知道。
3. **标签重映射成 0 起连续整数**（原始标签可能有缺口）：
   > 例：原标签 `[1, 2, 5, 10]` → `labels_to_index={1:0, 2:1, 5:2, 10:3}` → `self.labels` 存 `0/1/2/3`。
4. 算 `num_classes`、`cls_num_list`（每类样本数，类平衡采样会用，本次不用）；`self.parts` 只留可见部件（仅评估用）。

**`__getitem__`**：`拼路径 → pil_loader 读图 → self.transform(im) → 返回 (im, label)`。就这么简单——增强的复杂度都在 transform 里。

**跳过**：同文件的 `FineGrainedBirdClassificationParts`（带关键点/检测框）是**部件评估专用**，训练不碰，代码里有横幅。

### 2.4 dataset_utils.py —— 读图

**角色**：本次训练真正用到的只有 `pil_loader`：打开文件 → PIL 解码 → **统一转 RGB**。
转 RGB 是为了兼容灰度图/带透明通道的图（灰度会复制成三通道），保证后续张量都是 `[3, H, W]`。

其余函数（`center_crop_boxes_kps` 等带关键点的裁剪工具）是评估专用，代码里有"评估专用"横幅。

## 3. 模型搭建与架构

> **读这些**：`models/builder.py`（`load_model_ivpt`）→ `models/layers/transformer_layers.py` → `models/individual_landmark_vit.py` 的 `__init__` / `compute_xq` / `compute_feat`（**`forward` 留到第 7 章**）

这一章对应 `train_net.py` 第 6 步。这里只看**模型长什么样（静态结构）**——各个零件分别是什么、为什么需要它；
真正把它们串起来跑的 `forward` 是训练的"心脏"，放到第 7 章和单 batch 一起讲。

### 3.1 builder.py —— 模型工厂

`load_model_ivpt` 分两步：

1. `load_model_arch`：用 timm `create_model` 把主干建出来。本次走 `'patch'`（ViT）分支：加载 DINOv2 ViT-Base、
   `img_size=518`、训练时加 `drop_path`（本次 0）。建完会校验 `图像尺寸 % patch大小 == 0`（`518 % 14 == 0`，整除出 `37×37`）。
2. `init_ivpt_model`：把主干用 `IndividualLandmarkViT` 包一层，把所有 IVPT 专属开关（`n_pro`、`gumbel_softmax`、`modulation_type` 等）透传进去。

**跳过**：`ivpt_vit / ivptnet_vit / ivptnet_resnet101`（从网上拉训练好权重做推理的 hub 加载器）和 `ivpt_vit_bb / ivptnet_vit_bb`（坏死代码，传了类不接收的参数）都**不在训练路径**，代码里有横幅。

### 3.2 transformer_layers.py —— 带 qkv 返回的 block

**角色**：把 timm 原版的 `Attention / Block` 各派生一个"顺带返回 `q,k,v`"的版本（`AttentionWQKVReturn / BlockWQKVReturn`）。
`IndividualLandmarkViT.__init__` 里的 `convert_blocks_and_attention()` 会用**猴补丁**（直接改 `__class__`）把主干每个 block/attention 换成这两个版本——只换类、不动权重，所以行为和原版一致。

**⚠ 一个容易误解的点**：虽然它们能返回 `qkv`，但**本次训练其实没用到这个能力**：

- 训练 `forward` 里调 block 时只传一个 `x`（`x_k=x_v=None` → 退化成普通自注意力）；
- 且 `return_qkv` 默认 `False`，所以 `qkv` 三件套根本没被消费。
- "返回 qkv"是给**分析/可视化**的 `get_intermediate_layers` 那套方法（`return_transformer_qkv=True`）留的。

> 换句话说：这层包装在本次训练里只是"行为等同 timm 原版"，qkv 返回是顺带保留的功能。（自注意力下 `qkv` 投影还算了 3 遍，略浪费，但换来对交叉注意力的统一支持。）

### 3.3 individual_landmark_vit.py —— 核心模型（静态结构）

这是 IVPT 的核心类。先把**关键常量**钉住（本次配置）：

- `n_pro = [17,14,11,8,5]` → `num_landmarks = n_pro[-1] - 1 = 4`（4 个前景部件，末位那个名额留给"背景"）。
- `layer_n = len(n_pro) - 1 = 4` → 在**最后 4 个 block** 注入原型。
- `h_fmap = w_fmap = 518 // 14 = 37`；`num_prefix_tokens = cls(1) + register(4) = 5`。

**`__init__` 里新增的可学习组件**（只有这些 + 各 norm 会被训练，主干冻结）：

| 组件 | 形状 / 类型 | 作用 |
|---|---|---|
| `p_token[i]` | `[1, n_pro[i], D]`，5 组 | 注入的"原型 token"。前 4 组在 block 循环里注入，第 5 组（`[-1]`）用于最终读出 |
| `p_bias[i]` | `[1, n_pro[i], 37, 37]`，5 组 | 可学习**空间偏置**，加到距离图上再 softmax，给每个原型一个"倾向关注图里哪块"的先验 |
| `p_linear[i]` | `Linear(D→D)`，4 个 | 把聚合出的部件特征投影一下再拼回 token 序列 |
| `p_norm[i]` | `LayerNorm([N, D])`，4 个 | 规整部件特征 |
| `p_classifier[i]` | `Linear(D→N)`，4 个 | **软分配头**：把每个前景原型软分到 N 个部件上 |
| `modulation` | `LayerNorm([D, N+1])` | 分类前规整部件特征尺度 |
| `fc_class_landmarks` | `Linear(D→200, bias=False)` | 分类头（本次 `classifier_type='linear'`） |

主干的 `patch_embed / pos_embed / blocks(12) / norm / cls_token / reg_token` 都是**直接借用**（共享参数），不另起炉灶。

**两个关键 helper 的数学**（`forward` 会反复调它们）：

- **`compute_xq(x, q)` —— 算"原型 vs patch"的相似度图**
  入参 `x`=patch 特征图 `[B,D,H,W]`，`q`=原型 `[B,L,D]`；出 `maps=[B,L,H,W]`。
  用**负的平方 L2 距离**当相似度（越大越像）：`‖x−q‖² = ‖x‖² − 2·(x·q) + ‖q‖²`，再取负。
  代码里 `einsum('bchw,blc->blhw')` 算的就是点积 `x·q`。

- **`compute_feat(maps, x)` —— 按相似度图把 patch 特征聚成"每个槽一个特征"**
  对每个像素 `argmax` 选出"最像的那个槽"（硬分配），乘回 `maps` 值当权重；
  然后每个槽把分到的 patch 特征加权求和、再除以总权重 → 每个槽的**加权平均特征** `[B, N, D]`（含除零保护）。

> 这两个 helper 是"原型→部件图→部件特征"的原子操作。第 7 章的 `forward` 就是反复用它们 + softmax + Gumbel + 拼回序列，把整套机制跑起来。

---

> **小结**：现在你知道了模型有哪些"零件"（原型、空间偏置、软分配头、调制、分类头）以及两个核心 helper 的数学。

## 4. 损失与优化器装配

> **读这些**：`engine/losses/builder.py` → `utils/training_utils/optimizer_params.py` → `utils/training_utils/scheduler_params.py`

这一章对应 `train_net.py` 第 8~10 步，做的是**"配置 → 对象"**的转换：把命令行里的损失权重、优化器类型、调度器类型，
变成实际的损失模块、`Adam`、`StepLR`。**注意**：这里只是"把系数和优化器准备好"，真正按这些系数把 8 个损失加起来、反向更新，是第 7 章的事。

### 4.1 losses/builder.py —— 损失装配

**`load_classification_loss`（分类损失，四岔路）**：按命令行在 mixup / TopK / 标签平滑 / 普通交叉熵 之间挑一个。
本次三个开关都没开 → 走最后的 `torch.nn.CrossEntropyLoss`，`mixup_fn=None`。返回 `[训练损失, 评估损失]`，评估恒用普通 CE。

**`load_loss_hyper_params`（辅助损失系数 + 等变仿射范围）**：

- 把 11 个损失系数打包成 `loss_hyperparams` 字典（本次大多 = 1）。**注**：`l_conc`（concentration）被打包进来了，但**训练器代码里从不读它**——典型的"装载但不用"。
- 构造**等变损失**要用的随机仿射范围：`degrees=[-90,90]`、`translate=[0.11,0.11]`、`scale=[0.8,1.4]`、`shear=None`（两个 shear 都 0）。

> **⚠ 关键区分**：这套"等变仿射范围"和第 2 章数据增强里的 `RandomAffine` 是**两码事、互不影响**：
> - 数据增强的 `RandomAffine`：在喂给模型**之前**对训练样本做随机变换（数据多样性）。
> - 这里的等变仿射：在 `_run_batch` 里把图变换后**再过一次模型**，用来检验"部件图是否随图同步变换"（几何稳定性，见第 7 章等变损失）。

### 4.2 optimizer_params.py —— 5 组分组学习率

**`layer_group_matcher_ivpt`** 是本章重点：它遍历模型参数，按名字把它们分到 **5 组**，每组配不同的学习率倍率和 weight decay；
**冻结主干也在这里做**（把主干参数的 `requires_grad` 关掉）。

| 组 | 哪些参数（按名字匹配） | 学习率 | weight decay |
|---|---|---|---|
| 主干（带 wd） | 主干里的权重矩阵（`ndim>1`） | `lr ×1` | 有 |
| 主干（不带 wd） | 主干里的 bias / norm（`ndim==1`） | `lr ×1` | 0 |
| finer | `cls_token`、`pos_embed`、`reg_token`、`p_bias`、`p_token` | `lr ×2e2` | 0 |
| modulation | `modulation`、`p_linear`、`p_classifier` | `lr ×1e4` | 0 |
| scratch | `fc_class_landmarks`（分类头） | `lr ×1e4` | 默认 |

**为什么倍率差到 `1e4`？** 主干是预训练好的、且本次被**冻结**，基准 `lr` 本身就极小（`0.866e-6`）；
而 finer/modulation/scratch 这些是**从零开始学**的新层，得用大得多的**有效学习率**才学得动。所以给它们乘上 `2e2 ~ 1e4` 的倍率。
（即：`scratch` 组的实际 lr ≈ `0.866e-6 × 1e4 ≈ 8.7e-3`，而主干就是 `0.866e-6`——但主干冻结了，这个值其实用不上。）

**两个要知道的点**：

- 即使 `freeze_backbone=True`，主干参数仍会被**放进优化器的参数组里**（只是 `requires_grad=False` 不更新）——会占一点优化器状态显存。
- `unfrozen_layers` 写死为空列表，所以对应的那条 `elif` 分支是**永不执行的死分支**。

**`build_optimizer`**：按 `optimizer_type` 造优化器，本次 `Adam`。
**`calculate_weight_decay`**：实现 AdamW 论文的归一化 weight decay：`wd = norm_wd × √(1/(每轮迭代数×轮数))`。本次 `norm_wd=0`，所以结果恒为 `0`。

### 4.3 scheduler_params.py —— 学习率调度

**`build_scheduler`**：按 `scheduler_type` 造调度器，本次 `StepLR`：`decay_t=4`、`decay_rate=0.5`、`t_in_epochs=True`（**按 epoch 走**，不是按 iteration）。

衰减算例（基准 lr ≈ `0.866e-6`，每 4 个 epoch ×0.5）：

```
epoch 0~3 : 0.866e-6
epoch 4~7 : 0.433e-6
epoch 8~11: 0.217e-6
...（每组参数都按各自的当前 lr 同比例衰减）
```

`cosine` 和 `linearlr` 两条分支本次不走。

### 5.1 ddp_utils.py —— 分布式与种子

- `multi_gpu_check`：`train_net.py` 第 7 步调用，可见 GPU > 1 才返回 `True`。本次单卡 → `False`（后续 SyncBN/DDP 全跳过）。
- `ddp_setup`：多卡才调，分 SLURM / `torchrun` 两条路读 rank、初始化 NCCL 进程组。本次不调。
- `set_seeds`：固定 Python/NumPy/Torch 的随机种子。**有两个要知道的坑**：
  - **⚠ 它强制 `cudnn.deterministic=True`、`cudnn.benchmark=False`** —— 这会**盖过 `train_net.py` 顶部设的 `benchmark=True`**（确定性优先）。
  - **⚠ `PYTHONHASHSEED` 被写死成 `"42"`**，没用上传入的 `seed_value`。
  - 多卡时种子按 `seed + rank` 偏移（让各卡随机序列不同），单卡 `rank=0` 无偏移。
- `calculate_effective_batch_size`：有效 batch = 每卡 batch × 卡数（本次 `12×1`），给第 4 章的归一化 weight decay 用。

### 6.3 _prepare_dataloader —— 采样器选择

`_prepare_dataloader`（单卡）/ `_prepare_dataloader_ddp`（多卡）按情形选采样器：

**要点**：用了自定义 sampler 时 `shuffle` 必须为 `False`（打乱交给 sampler）；没有 sampler 时（如训练 loader、全量评估 loader）才让 DataLoader 自己 `shuffle`。

### 6.4 epoch_fraction_sampler.py —— shard 切分

这个采样器实现"每个 epoch 只用一部分数据"：把全集切成 `ceil(1/fraction)` 份（`fraction=0.1` → 10 份），
用 `seed+epoch` 做确定性打乱，按 `epoch % 份数` **轮换**取其中一份。凑满 `ceil(1/fraction)` 个 epoch 就正好把全集过一遍。
单卡用 `EpochFractionSampler`；多卡版 `EpochFractionDistributedSampler` 多一步"把这份 shard 再均分给各卡 + 补齐"。

> **⚠ 一个跨文件的细节（值得注意）**：换 shard 靠 `set_epoch`，而训练器 `_run_epoch` 里 **只有多卡时才调 `dataloader.sampler.set_epoch(epoch)`**。
> 所以**本次单卡**下，`test_loader` 的采样器 `epoch` 一直停在初始值 `0` → `shard_id = 0 % 10 = 0` → **每次中途评估都评的是同一个 10% 子集**（最终全量评估不受影响）。这对"中途准确率"的解读有意义：它是固定那一片的成绩，不是全测试集的无偏估计。

## 7. 训练主循环与 8 个损失（心脏）

> **读这些**：`distributed_trainer_ivpt.py` 的 `train` / `_run_epoch` / `_run_batch`（训练分支）→ `individual_landmark_vit.py::forward`（第 3 章留的坑，这里填）→ `reversible_affine_transform.py` → 7 个损失体（`engine/losses/*.py`）

这是整个训练步的"心脏"。前面所有"配料"——数据、模型零件、损失系数、3 个 DataLoader——在这里被真正串成一次次更新。
（沿用第 0.6 节的缩写：`B/D/H=W=37/L=1369/N=4/前缀5`。）

### 7.1 三层循环结构

训练是三层嵌套：

```
train()                      # 外层：epoch 1..25
 └─ _run_epoch(train=True)   # 中层：遍历一个 epoch 的所有 batch
     └─ _run_batch(...)      # 内层：一个 batch 的前向+8损失+反向
```

- **`train`**：每个 epoch → `model.train()` → `_run_epoch` 训练一轮 → 记 4 组分组 LR → 每 `save_every=10` 存档 →
  每 `eval_every_n_epochs=5` 用 10% 测试集**定期评估**（刷新最高就存 `best`）→ 全部跑完后在**全量**测试集做最终评估。
- **`_run_epoch`**：多卡才 `sampler.set_epoch` → 算 `vis_att_maps` 触发标志（epoch 1 / 每 10 / 最后一轮）→ 清零所有 `AverageMeter` →
  遍历 batch（搬到 GPU → `_run_batch` → 更新 loss/acc meter → `scheduler.step_update`）→ epoch 末取平均、训练时 `scheduler.step(epoch)`。
- **`_run_batch`**：单步，见 7.3。

### 7.2 forward —— 部件是怎么长出来的

（这是第 3 章特意留到这里的核心。`individual_landmark_vit.py::forward`，分 3 段。）

**第 ① 段 · 嵌入**：`patch_embed` 把图切成 patch token → `_pos_embed` 加位置编码并拼上 5 个前缀 token → `[B, 5+1369, D]`。

**第 ② 段 · 最后 4 个 block 注入原型**（`for i, block`：前 8 个普通过；`i≥8` 进入注入分支）：

1. 取该 block 的 patch 特征图：`norm(x.detach())` → 去掉 5 前缀 → 摊成 `[B, D, 37, 37]`。
2. `compute_xq` 算原型与每个 patch 的相似度图 `[B, n_pro[i], 37, 37]` → 加 `p_bias[i]` → **沿原型维 softmax**（每个 patch 得到"属于各原型"的分布）。
3. `compute_feat` 把 patch 特征按图聚到每个原型上 → 每原型一个特征。**约定：最后一个原型 = 背景，前 `n_pro[i]-1` 个 = 前景原型。**
4. `p_classifier[i]` 把每个**前景原型**映到 `N=4` 个部件上 → **`gumbel_softmax`** 得到"前景原型 → 部件"的（近似硬）软分配（空原型用 `1/N` 兜底）。
5. **按分配归并**：把前景原型的「特征」和「空间图」分别按软分配权重加权求和 → 得 `N` 个部件的特征 `[B,N,D]` 和空间图 `[B,N,L]`；再拼回背景 → `N+1`。这张 `[B,N+1,L]` 存进 `m_buffer`（consistency 损失要用）。
6. 部件特征过 `p_norm`/`p_linear`，作为 `N` 个"部件 token" `cat` 回序列 → 带着它们过这个 `block`（让部件 token 参与注意力，影响下一层）。

**第 ③ 段 · 最终读出 + 分类**：用第 5 组原型 `p_token[-1]`（`n_pro[-1]=5=N+1`）对 5 个缓存位点各算一张部件图（`maps_list`）→
取最后一张把最终层 patch 特征聚成每个部件一个特征 → `modulation`（LayerNorm 规整）→ `fc_class_landmarks` **只对 N 个前景部件**出分 → `scores [B,200,N]`。

**返回 5 个输出**（第 7.3 节会用到）：

```
all_features_mod [B,D,N+1]   # 调制后部件特征   → 正交损失
maps_list[-3]                # 倒数第 3 张部件图（_run_batch 没实际用）
scores [B,200,N]             # 各部件类别分     → 平均成最终 logits
map_feat = maps_list (5 张)  # 各位点部件图     → TV/presence/等变/像素熵
(m_buffer, qm_buffer)        # m_buffer 5 张空间图 → consistency；qm_buffer → 评估可视化
```

### 7.3 _run_batch 训练分支 —— 输出喂给损失

一个 batch 的完整一步：

1. `autocast`（本次未开 AMP）→ `forward(source)` 拿到上面 5 个输出。
2. `outputs = scores.mean(dim=-1)` → 把 `N` 个部件的类别分**求平均** → 每张图最终 logits `[B,200]`。
3. `target = m_buffer[-1].detach()` → 最深层部件图当 consistency 的目标（detach 不回传）。
4. **等变第二次前向**：采一组随机仿射参数 → 变换原图 → `model(变换图)[3]` 取它的 `maps_list` 作为 `equiv_maps`。
5. **算 8 个损失并相加**（见 7.5；很多项是"对 `maps_list` 的 5 张图各算一次再平均"）：

   ```
   loss = 分类 + 一致性 + presence + 正交 + 等变 + 全变差 + enforced_presence + 像素熵
   ```
6. **反向更新**：`optimizer.zero_grad(set_to_none=True)` → `loss.backward()` → `clip_grad_norm_(≤2.0)` → `optimizer.step()`。
7. 各项 `.item()` 记进字典，供打印/累计。

### 7.4 reversible_affine_transform.py —— 等变变换

为等变损失服务的工具：

- `generate_affine_trans_params`：在范围内随机采 `angle / translate / scale / shear`（本次 ±90° / 0.11 / [0.8,1.4] / 无）。
- `rigid_transform`：正向 = 一次 `affine`；`invert=True` 时按**相反顺序、相反量**逐步抵消（先 `-translate`，再 `-angle`、`1/scale`）。

> 等变的核心思想：理想模型应满足 `T⁻¹( f(T(x)) ) ≈ f(x)`——把图变换 `T` 再过模型、再把结果变回去，应当和原图的结果对齐。

### 7.5 8 个损失体 —— 各自罚什么

| # | 损失 | 罚什么（一句话） | 作用于 forward 的 | 权重 |
|---|---|---|---|---|
| 1 | 分类（CE） | 预测类别要对 | `scores.mean` 出的 logits | `l_classification` |
| 2 | consistency | 浅层部件图要像最深层（KL） | `m_buffer[:-1]` vs `m_buffer[-1]` | 固定 |
| 3 | total_variation | 部件图空间要平滑、连片 | `maps_list` 每张 | `l_tv` |
| 4 | presence | 每个部件至少一处被强激活 | `maps_list` 每张**前景** `[:,:-1]` | `l_presence` |
| 5 | orthogonality | 各部件特征互不相似 | `all_features` | `l_orth` |
| 6 | equivariance | 几何变换下部件位置稳定 | `maps_list[i]` vs `equiv_maps[i]` | `l_equiv` |
| 7 | enforced_presence | 背景占据图像边缘（把前景挤向主体） | `maps_list` 每张 | `l_enforced_presence` |
| 8 | pixel_wise_entropy | 每个像素的部件归属更"硬" | `maps_list` 每张 | `l_pixel_wise_entropy` |

各自的算法要点：

- **consistency**（`consistency_loss.py`）：`KL(target‖pred)=Σ target·log(target/pred)`，对前几层每层算一次再平均；target detach。
- **total_variation**（`total_variation.py`）：相邻像素差绝对值之和（水平+垂直），即图梯度幅值；归一化用 `B*H*W`（不含通道 C）。
- **presence**（`presence_loss.py`，`original` 变体）：`avg_pool` 平滑 → 取每图每部件空间最大值 → 跨 batch 取每部件最强响应 → `1 − mean`。逼每个部件在 batch 里至少一处强激活。`_run_batch` 只喂前景通道。
- **orthogonality**（`orthogonality_loss.py`）：部件特征单位化 → 两两余弦相似度（Gram 矩阵）→ 去掉对角线 → 非对角元素平方均值。越小越正交。
- **equivariance**（`equivarance_loss.py`）：把 `equiv_maps` 用 `T⁻¹` 变回 → 与原图部件图算余弦相似度 → `1 − mean`。（平移量按 `37/518` 缩放到部件图分辨率。）
- **enforced_presence**（`enforced_presence_loss.py`，`enforced_presence` 变体）：用"离中心越远权重越大"的**径向 mask** 加权 → 取背景通道最强响应 → 与全 1 做 BCE。逼背景在四周有强响应。
- **pixel_wise_entropy**（`pixel_wise_entropy_loss.py`）：逐像素在部件维上的分类熵的均值；熵越低越接近 one-hot。配合 Gumbel 用，先 `clamp`+重归一化保数值稳定。

### 8.1 _run_batch 评估分支

当 `train=False`（定期评估 / 最终评估 / 纯评估模式）时走这里，比训练分支简单得多：

### 8.2 visualize_att_maps.py —— 把部件画出来

**`extract_and_resize_patch`**：给定整图和某个部件的掩码，找出掩码的外接矩形（太小则向外扩一点），裁出该区域、缩放到 `64×64`。
就是"把这个部件覆盖的那块图抠出来"。

**`show_maps`**（本次训练会触发——在 epoch 10/20 的定期评估、以及最终评估时）：

1. 把图反归一化 + 缩到 `256×256`；把部件图插值到 `256×256` 后沿部件维 `argmax` → 每个像素属于哪个部件 `[B,256,256]`。
2. **裁块**：对每个部件，把它在各图里覆盖的区域裁出来（用上面的 `extract_and_resize_patch`），拼成一张方形网格，
   存到 `results_hie_<subpath>/middle/<层>/<部件>/<epoch>_<iter>.png`（这些块是 eval-only 层级重排的素材）。
3. **叠加图**：用 `skimage.label2rgb` 把部件标签上色叠到原图上（背景不着色），在每块区域质心标上部件编号，
   整个 batch 拼成一张图存到 `results_vis_<subpath>/`。

> **小 quirk**：`__init__` 里 `num_parts = n_pro[0]+1` **只用第一层的原型数**定调色板大小；各层原型数不同时仅影响配色，不影响正确性。

**`show_maps_hie`**：eval-only 的层级可视化（仅 `enable_hierarchy_vis=True` 才由训练器的层级块传 `vis_flag` 调用）。
本次**不触发**，代码里有横幅、保持原样。
