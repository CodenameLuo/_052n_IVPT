# Part 0 —— 定位与封口模板

## 0.1 一句话定位（thesis）

> **把 IVPT 的「无监督部件原型 → 软分割 → 部件特征池化 → 部件级投票分类」这条主干机制，
> 删繁就简后移植到预训练 ViT 的 CIL 框架中，并为「原型随任务增量到来」设计专门的
> 扩展与隔离机制，得到一个每次预测都能回答『哪个部件、在图像哪里、给哪个类投了票』的
> 类增量学习方法；在标准 CIL 协议上与 L2P/CODA-Prompt 等 prompt 系方法精度可比，
> 同时提供它们都不具备的部件级内生（ante-hoc）可解释性。**

三条根据，说明这个 thesis 站得住、不是硬凑：

1. **IVPT 和 prompt 系 CIL 方法本来就是同族结构**。IVPT 的骨架是「冻结 DINOv2 backbone +
   在后几层把可学习 token 拼进序列一起过 block」（FL Part 0.4 总览、Part 6.6 注入），这和
   L2P/DualPrompt/CODA-Prompt 的「冻结 ViT + 注入可学习 prompt」在机制位置上完全同类。
   所以移植不是把两个异质系统嫁接，而是**同一赛道里换一种 prompt 的来源**。
   - **边界**：同族不等于相同。L2P 系的 prompt 是「参数池里检索出来的可学习参数」，IVPT 的
     prompt 是「当前图像的部件特征聚合出来的内容自适应向量」（FL Part 6.3/6.6）。这个差别
     既是本工作的创新落点（prompt 携带部件语义 → 可解释），也是最大风险点（内容自适应
     prompt 没有任务专属参数可冻结，防遗忘要靠原型侧设计，Part 5 正面处理）。
2. **部件级投票给了 CIL 稀缺的内生可解释性**。IVPT 的分类是 `scores [B, 类, 部件]`——每个
   部件独立给所有类打分再平均（FL Part 8.5），证据链是现成的：软分割图回答「部件在哪」，
   `scores` 切片回答「这个部件投了谁」。现有 prompt 系 CIL 没有一个能把单次预测分解到
   这种粒度——它们的可解释性最多到「检索了哪个 prompt」（key 匹配权重），离「图像里的
   哪块区域支持了这个决策」差一整层。
   - **边界**：「可解释」要可量化才能写进论文，不能只贴热图。Part 7 必须给出部件一致性 /
     跨任务部件稳定性的数值指标，否则 claim 退化成定性展示。
3. **IVPT 的 8 个损失里 7 个不吃类别标签**。除 classification 外，consistency/tv/presence/
   orth/equiv/enforced_presence/pixel_entropy 全是作用在软分割图或部件特征上的自监督正则
   （LD 速查表）。这意味着部件塑形机制**与类监督解耦**，新任务来了照常用，不存在「旧类
   标签不在了正则就失效」的问题——这是它比很多需要类监督辅助损失的方法更适合 CIL 的
   结构性原因。
   - **边界**：不吃标签 ≠ 不受任务影响。原型本身是参数，新任务训练会动它们；正则不防遗忘，
     防遗忘是 Part 5 的事，两件事不要混。

## 0.4 全文的论证主线（预告，给后面各 Part 定基调）

后面 Part 1~5 的所有取舍，都围绕**同一对矛盾**展开，这里先把它摆上桌面：

- **IVPT 的原型是「全数据联合训练」出来的**：8/6/5/4 套原型一起在完整数据集上学，
  softmax 沿通道维竞争（FL Part 3，`dim=1`）意味着任何一个原型变了，**所有** patch 的
  软分割分布都会变。
- **CIL 的本质是「数据按任务切片到来」**：任务 t 训练时看不到任务 1..t-1 的数据。如果
  新任务的训练改动了旧原型、或新增原型挤进了 softmax 竞争，旧类图像的软分割图就会漂移
  ——这是**部件层面的遗忘**，发生在分类头之前，是 prompt 系 CIL 文献里没有人正面处理过的
  遗忘形态。
- 所以本方法的创新点不是「把 IVPT 跑在 CIL 协议上」，而是：**删掉 IVPT 里为单数据集
  联合训练服务的复杂度（层级路由、多套原型、部分正则），把省下的设计预算花在「原型的
  增量扩展、竞争隔离、部件语义锚定」上**——前者是 Part 3/4 的「删」，后者是 Part 5 的「改」。
  「删」和「改」共用同一个理由系统，整份文档才成一个论证而不是两张清单。

## 1.4 一眼看清「删的是什么」：一整个层级机制群，不是零散五件

被删的 **C5 / C8 / C9 / L2 / L6**（加上 C11 被删的「逐层变粗」半边）不是各自独立的判决，
而是**同一个机制群**——IVPT 为「层级部件可解释性」配的全套支撑系统：

```
多套逐层变粗的原型（C3 旧形态 + C11 半边）＝ 层级的本体
        细→粗路由（C8）＝ 层级的生成器
   两路 detach 聚合（C9）＝ 路由的训练管线
     consistency（L2）＝ 路由的监督信号（FL Part 6.5：路由只由它学）
        p_bias（C5）＝「内容相同的细原型」能被空间切开的前提（FL Part 3.3）
         equiv（L6）＝ 与 C5 强耦合的几何正则（FL 笔记已标注两者天然张力）
```

★ **拔掉「层级」这一个卖点，整个群一起失去存在理由**。这就是「删繁就简但不失主体」的
结构性依据：删的是一个自洽的子系统（它内部互相依赖、对外只为层级服务），留下的主干
（C1/C2/C4/C6/C7/C10/C12/C13/C14）不依赖它也能独立运转——前置笔记里「收尾读出用最终图
直接池化、不经过路由聚合」（FL Part 8.3 两次 compute_feat 的对比）正是这条主干能独立
运转的现成证据。

⚠️ **诚实标注（删层级失去什么）**：fine→coarse 层级是 IVPT 论文标题里的卖点，删掉它，
「部件层级树」这种可视化就没有了。我们的可解释性卖点必须**换轴**——从「单数据集内的
部件层级深度」换到「**跨任务的部件语义稳定性**」（任务 1 学出的「头」原型，到任务 10
还稳定指着头部区域）。这是换轴而非降级：后者与 CIL 的核心关切（遗忘）同构，是 prompt 系
baseline 完全没有的维度；但审稿人若拿 IVPT 对照问「层级哪去了」，Part 3 的论证就是

# Part 2 —— 保留的主体：为什么这条主干正好是可解释 CIL 要的

## 2.1 删完之后剩下的主干（先看全貌）

把 Part 1 判「删」的层级机制群全部拿掉、把判「改」的组件先按「思想保留」的形态画进来
（实现细节 P5 定），剩下的前向是这样一条干净的单链：

```
img → 冻结 backbone（前段纯 blocks，C1）
   ↓
[后 K 个注入层，共享同一套部件原型]                    ← C11 改后的形态
   x_ 特征图重建（norm+detach+unflatten，C2）
   → compute_xq：原型↔patch 负欧氏距离（C4）
   → 通道 softmax：patch 在部件间站队 → 软分割图（C6 思想）
   → compute_feat：掩码池化 → 部件描述向量（C7）
   → p_norm/p_linear → prompt，拼回序列过 block（C10，P5 详）
   ↓
[读出]
   干净重算最终软分割图 +1e-6（C12 简化版）
   → compute_feat 第二次：最终图池化部件特征（C7）
   → modulation 重标定（C13）
   → 部件投票：scores [B, 类, 部件] → mean → outputs（C14 思想）
```

对照 FL Part 0.4 的 IVPT 原版总览：少掉的正是每个注入层内部的「路由 → 两路聚合」那一段
和跨层的 `m_buffer`/`qm_buffer` 记账——**每层内部从 6 步变 4 步，跨层从 4 套原型变 1 套**。
下面逐组件给「根据 → 论证 → 边界」。

## 2.2 C1 冻结 backbone —— 两边需求恰好重合

- **根据**：IVPT 的部件机制整个建在冻结 DINOv2 之上，且找部件时对特征 `x.detach()`
  （FL Part 1.2）——说明它的部件发现**从设计之初就不依赖 backbone 被更新**。
- **论证**：冻结 backbone 是 L2P 以来全部 prompt 系 CIL 的共同前提——冻结即天然不遗忘的
  特征底座，所有防遗忘设计都只需照看冻结层之外的小参数。IVPT 恰好也只要冻结特征。
  **两边需求重合，这一环移植零成本**，而且是和 baseline 同台可比的公平性前提。
- **边界**：⚠️ backbone **选哪个**是真实的实验风险点。IVPT 用 DINOv2（其特征的部件涌现性
  是整套机制能转的隐性前提），而 PILOT 里 prompt 系 baseline 的标准配置是 ImageNet-21k
  监督 ViT。公平比较要求同 backbone 重跑 baseline（PILOT 支持换 backbone，工程上可行），
  但「DINOv2 上 L2P 表现如何」没有现成文献数字兜底——P7 必须把这个变量的实验设计写死。

## 2.3 C2 特征图重建 + detach —— 解耦在 CIL 里升值

- **根据**：`norm(x.detach())` → 切前缀 → unflatten 摊回网格（FL Part 1.2）。纯几何操作 +
  一个关键 detach：部件分支的梯度不回灌给主序列。
- **论证**：几何部分与任务无关，照搬。detach 的意义在 CIL 下**升值**：主序列里不只有冻结
  backbone 的激活，还有**前面注入层已经拼进去的 prompt**——detach 切断了「任务 t 的部件
  正则 → 特征通路 → prompt」这条间接污染回路，使「部件发现」和「特征精炼」两个回路保持
  解耦。在 IVPT 里这只是训练稳定性的设计；在 CIL 里这是**防新任务正则隔空改写承载旧知识
  的注入参数**的隔离墙。
- **边界**：detach 也意味着部件正则无法通过特征通路帮特征变好——IVPT 里「部件→特征」的
  正向影响全靠 prompt 注入这条显式通路实现。我们删了细→粗聚合后，这条通路改为直通
  （C10，P5 详），影响通路仍在，不因 detach 而失血。

## 2.4 C4 compute_xq 负欧氏距离 —— 度量「语义内容」而非检索「参数地址」

- **根据**：`‖q−x‖²` 三项展开成相似度图，原型=特征空间中的一个点（FL Part 2）。
- **论证**，三条：
  1. **无参数算子**。距离计算本身没有任何可学参数——不随任务增长，没有遗忘载体。
  2. **与语义锚定初始化同度量**。P5 计划用任务数据特征的聚类质心初始化新原型，而
     k-means 聚类本身就是欧氏度量——初始化和相似度计算用同一把尺子，新原型放进去
     **第一步就能产生有意义的软分割**（质心附近的 patch 自然最近），冷启动不抢错区域。
     这是「负欧氏距离」比「可学的 query-key 打分」更适合增量场景的具体理由。
  3. **和 L2P 系的本质分工**。L2P/DualPrompt/CODA 的 query-key 余弦匹配检索的是
     「该用哪份参数」（地址），我们的距离图度量的是「图像内容里哪块像这个部件」（内容）。
     前者的匹配权重解释不了图像，后者直接就是空间证据——这是证据链的根。
- **边界**：欧氏距离对特征尺度敏感。同一数据集内任务间的尺度漂移很小（backbone 冻结），
  但跨域协议（如 ImageNet-R 的风格多样性）下 patch 范数差异会进入 `b_sq` 项——前置的
  LayerNorm（C2 里的 `norm`）承担尺度稳定，这个依赖要在消融里验证而不是默认成立。

## 2.5 C6 通道 softmax（思想半边）—— 竞争产生分割，分割承载解释

- **根据**：softmax 沿通道维（`dim=1`），每个 patch 在全部原型上归一成竞争分布
  （FL Part 3，「这一个 patch 在 N 个原型里怎么分配」）。
- **论证**：**竞争是「分割」之所以成立的形式基础**。没有竞争（比如每个原型独立 sigmoid），
  得到的是 N 张互相重叠的热图——attention 可视化那种「处处有点亮」的糊图，部件区域不
  互斥，「这个 patch 属于哪个部件」无定解，证据链第一问（部件在哪）就答不干净。竞争
  强制每个 patch 站队，部件图才互斥成块、才可读。可解释 CIL 要的「旧任务的解释不变」
  本质上就是「旧图像的站队结果不变」——所以软分割图是旧任务可解释性的**载体**。
- **边界**：竞争是双刃剑，这正是 0.4 那对矛盾的着力点：全局竞争下，新任务原型一进来，
  旧图像每个 patch 的归一化分母都变了，站队结果整体漂移——「改」的那一半（竞争范围
  怎么划）是 P5 的核心设计，此处只立论「竞争本身必须保留」。

## 2.6 C7 compute_feat 掩码池化 —— 无参数读出 + 自带诊断副产物

- **根据**：argmax 硬分区 + 软置信加权平均 → 部件描述向量 `[B, N, D]`；副产物
  `count_map` = 每部件抢到的软质量；空原型除零兜底（FL Part 4）。
- **论证**，三条：
  1. **无参数**。和 C4 一样，池化算子本身没有可学参数——部件特征怎么从图里读出来，
     这个「读法」永远不会被新任务改写。
  2. **输出形状与类无关**。`[B, N_parts, D]` 里没有类维度——类增量时这一环**一行代码
     都不用动**，增量复杂度被推到它下游的分类头（C14）一处。
  3. **count_map 在 CIL 里有新用途**。IVPT 里它只是除法的分母；CIL 里「部件 k 在旧任务
     图像上抢到的质量」随任务的变化曲线，就是**部件级遗忘的直接观测量**（部件还在不在、
     被谁抢走了）——P7 的可解释性指标可以直接拿它当原料，不需要额外机制。
  4. （顺带）FL Part 8.3 已经演示过：收尾读出就是「干净图 + compute_feat」直接池化、
     不经过路由聚合——**主干绕开层级独立运转，在 IVPT 自己的代码里就有现成先例**。
- **边界**：argmax 在平局处的退化（body-C 那种空原型）在增量下概率更高——新原型冷启动
  时最容易一个 patch 都抢不到。对策不在这一环改机制（兜底逻辑保留），而是靠 L4 presence
  继续防坍缩 + P5 的锚定初始化让新原型出生就有自己的领地。

## 2.7 C12 干净重算（简化版）—— 三条理由活下来两条半

- **根据**：FL Part 8.2.3 重算的三条理由：① 补从没算过的读出层；② per-map 正则需要
  细图而循环里的图用完即弃；③ 统一公式 + 1e-6 防 `log(0)`。
- **论证**：删层级后只剩一套原型，但注入循环里每层算的软分割图**依然用完即弃**（被
  compute_feat 消费掉就丢），而保留的四个 map 正则（L3/L4/L7/L8）和分类读出依然需要
  一张统一口径、数值加固的图——理由 ②③ 原样成立，理由 ① 退化为「读出图本来就要算」。
  简化收益实打实：原来要重算 4 套（8/6/5/4 通道），现在**只对读出层重算 1 张**。
- **边界**：默认正则只作用在读出层的重算图上（开销最小）。若 P5 的设计需要约束中间
  注入层的图（比如发现跨层部件漂移影响 prompt 质量），重算次数才相应增加——按需扩展，
  默认不开。

## 2.8 C13 modulation —— 留，但增量形态要先打个预防针

- **根据**：`LayerNorm([D, N])` 把整组部件特征联合归一化，部件自己的通道块拉到 ≈+2、
  其余压到 ≈−0.5，对比放大后分类头更好下刀（FL Part 8.4）。
- **论证**：参数量可忽略（2×D×N 个仿射参数），效果是让「部件的票」更有区分度——留。
- **边界**：⚠️ **形状绑定部件总数 N**。若 P5 决定部件数随任务增长，`LayerNorm([D, N])`
  的归一化维度会变，旧仿射参数对不上号。预案已想好：改成**逐部件独立的 `LayerNorm([D])`**
  （每个部件向量自己归一化）——归一化语义基本不变（仍是重标定 + 对比放大），但形状与 N
  解耦，增量安全。两种形态的选择跟着 P5 的「部件数固定 or 增长」一起拍板，不单独悬置。

## 2.9 C14 部件投票（思想半边）—— 加性证据结构是整个方法的灵魂

- **根据**：所有部件共享一个 `fc: D→类数`，每部件独立打分得 `scores [B, 类, 部件]`，
  沿部件平均成 `outputs`（FL Part 8.5）。
- **论证**，三条：
  1. **这是证据链第三问的落点**。「头投了 cls2、翅投了 cls7」这种逐部件读票（FL Part 8.5
     的 scores 切片）是事后归因方法（Grad-CAM 之流）给不出的**内生**分解——模型的 logit
     在代数上就等于部件票的平均，解释即计算本身，不是计算之后的近似重构。
  2. **共享 fc 是部件可比性的来源**。所有部件过同一个线性头 → 部件特征被迫住进同一个
     语义空间 → 不同部件的票才可比、才能平均。如果每部件配独立头，票的尺度互不可比，
     「谁投了谁」的解读就失效。共享头还顺带把分类参数压到最小（一份而非 N 份）。
  3. **加性结构 = 遗忘可分解**，这是 CIL 角度最值钱的性质：
     `logit(c) = mean_k score(部件 k, c)`。旧类精度下降时，可以逐部件追责——是部件 k 的
     **定位**坏了（软分割漂移，count_map/分割图可查），还是定位没坏但它的**票**变了
     （fc 或部件特征漂移，score 切片可查）。遗忘从一个标量（精度掉了）变成一张可定位的
     账单。这是 0.2 封口模板里二级 fallback（遗忘诊断分析）的全部技术基础，也是八个
     baseline 谁都给不出的分析能力。
- **边界**：部件平均投票隐含「每类的证据均匀摊在各部件上」。细粒度场景常靠单一判别部件
  （鸟喙形状定种），平均会稀释强证据。IVPT 原文同样是平均投票（它的主场就是细粒度），
  说明稀释在实践中可承受——**默认保持平均**。诚实预案：若实验证明这是精度瓶颈，可加
  部件权重，但代价是证据链多一层间接（票要乘权重才是真贡献），与「解释即计算」的卖点
  相抵——所以这是最后手段，且若启用必须连可解释性展示一起改，不是免费旋钮。

## 2.10 主干的「CIL 体检表」——删繁就简的直接收益

把保留主干的每一环放到 CIL 最关心的三个问题下过一遍：**有没有随任务增长的参数？吃不吃
类别标签？新任务训练能通过哪条通道改变旧任务行为？**

| 环节 | 可学参数 | 吃标签? | 新任务影响旧行为的通道 |
|---|---|---|---|
| C1 backbone | 冻结 | 否 | 无 |
| C2 重建+detach | 无 | 否 | 无 |
| C4 compute_xq | 无 | 否 | 无（算子本身） |
| C6 softmax 竞争 | 无 | 否 | ★有——竞争分母随原型集合变（P5 主战场） |
| C7 compute_feat | 无 | 否 | 无（算子本身） |
| C10 prompt 投影 | p_norm/p_linear | 否 | ★有——投影参数被新任务更新（P5） |
| C12 重算 | 无 | 否 | 无 |
| C13 modulation | 极少 | 否 | 小（随 P5 形态定） |
| C14 投票头 | fc（共享） | 是 | ★有——fc 被新任务更新（P5） |
| 部件原型本体 | p_token | 否 | ★有——原型被新任务更新（P5） |

★ **这张表就是删繁就简的最大收益**：整条主干里，「新任务能伤到旧任务」的入口只剩
**四个小参数组**——部件原型 `p_token`、竞争范围（原型集合）、prompt 投影 `p_norm/p_linear`、
共享分类头 `fc`（外加联动的 modulation）。其余环节全是无参数算子或冻结参数，物理上
不可能遗忘。对照 IVPT 原版：层级机制群里的 `p_bias`（随任务长）、`p_classifier`（路由头，
要被新任务更新）、4 套原型（4 倍入口）全被删掉了。**Part 5 的防遗忘设计只需要照看这
四个入口**——问题面被结构性地收窄了，这就是「删」与「改」共用同一理由系统的含义
（0.4 主线的兑现）。

# Part 3 —— 删除的论证：层级机制群为何在 CIL 下消失或变害

## 3.1 删除的判据（总原则，先立规矩）

一个组件该删，当且仅当满足下面两条之一，且「失去的东西」有明确的补偿或换轴方案：

- **(a) 问题消失**：它在 IVPT 里服务的问题，在我们的 CIL 设定（单套原型、增量到来）下
  不复存在；
- **(b) 问题变害**：它在 CIL 下产生 IVPT 单数据集联合训练时没有的新害处——新增遗忘入口、
  参数随任务增长、解释不可复现、训练成本不可摊销——且害处无法用小改修复。

下面每个组件都按「① 为 IVPT 解决什么（根据）→ ② 在 CIL 下哪条判据命中 → ③ 失去什么、
怎么补」三段走。注意删除顺序有逻辑：**先删 C8 路由（层级的生成器），C9/C5/L2 的存在
理由随之塌掉**——这正是 1.4「机制群」论断的展开。

## 3.2 C8 细→粗路由 —— 第一张多米诺骨牌

- **① 为 IVPT 解决什么**：层级可解释性的生成器。细原型（head-L/head-R）经
  `p_classifier` + softmax 软分配进粗部件（头），`q_maps` 就是层级树的边
  （FL Part 5.4 那张 7×3 干净路由表）。它存在的前提是「细原型数 > 粗部件数」——
  IVPT 为了层级有足够细度，**故意超额配原型**。
- **② CIL 下两条判据都命中**：
  - **(a) 问题消失**：单套原型下细=粗，没有「并」的对象，路由无事可做。
  - **(b) 问题变害**，三笔账：
    1. `p_classifier` 是一个被持续训练的 `Linear`——新任务更新它，旧任务图像的部件
       **分组本身**就变了。这是「路由级遗忘」：旧图的解释树被无声重写，又多一个要防的
       入口（对照 2.10 体检表的收窄方向，留着它就是逆行）。
    2. 真实配置走 `gumbel_softmax`（FL Part 5.3）——采样带随机性，同一张图两次前向
       可能给出不同的层级归属。单数据集训练里这是探索噪声；对「解释」这是坏性质：
       **可解释方法的解释必须可复现**，靠采样的路由天然违背。
    3. 它是空原型退化的温床：body-C 的整套兜底（除零、count_mask、masked_fill 1/3）
       和稀释/泄漏问题（FL Part 6.3/6.4 的 0.81 稀释、0.18 泄漏）全是路由带来的复杂度。
  - 还有一条**漂移链**：路由的训练信号只有 consistency（FL Part 6.5 autograd 实验：
    路由只由它学），而 consistency 的老师（收尾图）在 CIL 下本身随任务漂移——老师漂、
    路由跟着漂、层级树跟着漂。IVPT 里老师是全数据上稳定收敛的；CIL 里这条链每个环节
    都在动，解释的「树」没有锚。
- **③ 失去什么、怎么补**：失去 fine→coarse 层级树。两手补偿：
  1. **卖点换轴**（1.4 已立论）：可解释性卖点从「层级深度」换到「跨任务部件语义稳定性」。
  2. **层级需求降级为离线分析**：若论文展示真需要「部件分组」视图，对训练完的原型做
     **事后聚类可视化**（k-means over 原型向量）即可——零参数、零训练耦合、零遗忘风险，
     是分析手段不是方法组件。★ 这不算开口子：它不进训练图、不进方法主张，只是附录级
     可视化的备选。

## 3.3 C9 两路 detach 聚合 + `m_buffer`/`qm_buffer` —— 随路由塌掉，但精神被继承

- **① 为 IVPT 解决什么**：给路由安排干净的训练信号分工——特征路 detach 让分类改不动
  路由、空间图路不 detach 让 consistency 专管路由（FL Part 6.5 那对「一个 None、一个
  非零」的梯度铁证）；`m_buffer` 给 consistency 喂粗图、`qm_buffer` 给层级可视化记账。
- **② CIL 下判据 (a) 直接命中**：它分工的对象（路由 C8）和监督方（consistency L2）都
  没了，整套不对称机关失去服务对象。不需要独立论证——这就是「机制群」的含义。
- **③ 失去什么、怎么补**：
  - **「防分类污染结构发现」的精神不能丢，但已经被更简单的机制继承**：保留主干里
    `compute_feat(maps.detach(), x)` 本来就把软分割图 detach 掉再喂池化（FL Part 4.1
    输入注），即「分类/prompt 的梯度改不动分割结果」这层隔离，在 IVPT 现有代码里就由
    一个普通 detach 实现着——不需要两路不对称这种精巧机关来重新发明。⚠️ 但要诚实记一笔
    工程账：原型 `p_token` 仍同时被「分类 CE（经读出图）」和「部件正则」两路训练，
    「分类要不要被允许塑形原型」在 CIL 下是真问题（分类拉原型=任务偏置入侵部件语义），
    P5 设计原型更新规则时必须明确给出答案，不能默认沿用。
  - `m_buffer` 的跨层粗图记账没了 → 跨层对比的素材没了。但单套共享原型下，各注入层的
    软分割图**天然同通道可比**（同一通道=同一部件），想看跨层直接并排画即可，不再需要
    「先聚合到统一 4 通道」这道工序——记账的需求和机制一起消失。
  - ★ 顺带的审计收益：删掉 `q_maps` 后，FL Part 6.5 那两条梯度路径不复存在，「哪个 loss
    能改哪个参数」的梯度账本变短——CIL 下审计遗忘入口（2.10 表）因此更容易做、更容易信。

## 3.4 C5 `p_bias` 空间先验 —— 最激进的一刀，论证要最扎实

- **① 为 IVPT 解决什么**：把**内容上完全相同**的超额细原型在空间上切开。FL Part 3.3 的
  softmax 表格是铁证：head-L 和 head-R 的相似度一模一样（−0.020），全靠 +3.0 的 bias
  让左头 patch 判给 head-L（0.951 vs 0.047）。它是「超额配原型」的配套设施。
- **② CIL 下两条判据都命中**：
  - **(a) 问题消失**：单套原型、每个原型对应一个语义部件，不再有「内容相同要靠位置
    切开」的原型对。配套设施随主体（超额原型）一起失去服务对象。
  - **(b) 问题变害**，三笔账：
    1. **固定空间先验=全局位置假设，CIL 下两难**。`p_bias` 说的是「这个部件通常长在画面
       这个位置」——这是对**全数据分布**的断言。增量场景里新任务的类分布没见过：bias
       若继续训练，被新任务拖走 → 旧图像的软分割漂移（新增遗忘入口）；若冻结 → 新类
       被旧任务的位置先验错误束缚。可训练和冻结都不对，结构性两难，删是唯一干净解。
    2. **随原型数增长的参数表** `[N, H, W]`：P5 若选原型增量，bias 也要跟着增量管理，
       白添一组要防遗忘的参数（再次逆着 2.10 的收窄方向）。
    3. **与等变性天然冲突**（笔记里现成的）：图转了、bias 不转，部件被钉死在固定坐标
       ——FL/LD 损失 6 已诚实标注这正是 equiv loss 偏大的头号原因。IVPT 接受这对内部
       张力；我们删 bias，顺手把张力拆掉（L6 的判决也因此少一个反对理由，见 Part 4）。
- **③ 失去什么、怎么补**：失去的是**空间正则化**——即便内容有歧义，部件也不会在画面上
  乱跳的那份稳定性。补偿分三层：
  1. **锚定初始化接管「分工」功能**（P5）：原型出生自任务数据特征的聚类质心，**内容上**
    就互相分开——分工从「空间切」改为「语义切」，更符合「部件=语义单元」的本意。
  2. 保留的 L3 tv + L8 pixel_entropy 继续管「空间成块、归属果断」，分割图的空间秩序
     不是只靠 bias 维持的。
  3. ⚠️ **已知风险，写进消融**：若实验出现部件位置抖动/碎片化，对策优先级为
     「加大 tv 权重 → 检查锚定初始化质量」，**重新引入轻量 bias 是最后手段**（它会把
     上面三笔害处一起带回来）。这是预编号的风险预案，不是开放设计分支。

## 3.5 C11 的「逐层变粗」半边 —— 删粒度阶梯，留多层注入

- **① 为 IVPT 解决什么**：层级语义的深度方向——浅层 8 个细原型、深层 4 个粗原型
  （FL Part 7.1），「不同深度不同粒度」既是层级可视化的素材，也对应「特征逐层抽象」
  的直觉。
- **② CIL 下判据 (b) 命中**：
  1. **多套原型=遗忘入口 ×4、增量机制 ×4**。每任务若要扩原型，得对 4 套各设计扩展、
     隔离、初始化——同一个问题解四遍，复杂度乘法增长，而收益（粒度阶梯）与 CIL 的
     核心关切无关。
  2. **各层原型数不同 → 跨层图不可直接比**，IVPT 才需要「聚合到统一 4 通道」这道工序
     （C9）来造可比性；单套共享原型后跨层天然可比，问题连同解法一起消失（3.3 已述）。
  3. 多层**注入**本身无罪有功——部件 prompt 逐层精炼主干特征是 IVPT 与 backbone 耦合的
     精华（FL Part 6.6），且注入深度 K 正好对齐 DualPrompt/CODA 「在哪几层放 prompt」
     的超参，公平比较容易设置。所以只删「变粗」、保留「多层」。
- **③ 失去什么、怎么补**：失去「不同深度不同粒度」的表达力。诚实评估这份损失的真实
  大小：DINOv2 后几层（恰好是注入发生的层段）的特征语义粒度本来就接近——都偏「物体/
  部件级」，8→6→5 的粒度差**更多是设计强加的，不是特征逼出来的**。⚠️ 这条是推断不是
  实证，所以把它变成现成的消融实验：「K 层共享一套原型 vs 各层独立原型」——这是论文里
  标准的 ablation 表行，不是开放设计分支。

## 3.6 损失侧 L2 / L6 的机制账（判决细节在 Part 4，这里只收尾机制逻辑）

- **L2 consistency**：老师（收尾干净图）和学生（聚合粗图 `m_buffer`）**两端都是被删机制
  的产物**——学生没了（C9 删）、老师的「干净」也依赖层级读出设定。加上 3.2 说的漂移链
  （CIL 下老师自己随任务动），它既无对象也无锚点。Part 4 只需补「删了之后跨层一致性
  要不要别的东西管」的答案。
- **L6 equiv**：3.4 已拆掉它与 `p_bias` 的耦合张力——这一点其实对 equiv **有利**（删
  bias 后等变性更可达成）。所以 L6 的最终判决**不取决于机制冲突，而取决于成本账**：
  唯一双前向 ×2 训练成本，在 CIL 多任务预算下买到的边际收益有多少——Part 4 算这笔账。

# Part 4 —— 8 个损失的逐个判决

## 4.1 L1 classification —— 改：CE 保留，作用范围 CIL 化

- **IVPT 里管什么**：唯一吃标签的损失，`CE(outputs, targets)`，`outputs` = 3 个部件
  投票的平均（LD 损失 1）。
- **CIL 下的问题**：任务 t 训练时只有新类数据。若 softmax 跑在**全部已见类**的 logit 上，
  旧类永远没有正样本 → 旧类 logit 被系统性压低，这是 CIL 的教科书级病灶。
- **改成什么样**：**局部 CE（logit 掩码）**——softmax 与 CE 只在当前任务的类列上算。
  这是 PILOT 系 prompt 方法的标准做法，采用它同时是公平性要求（baseline 都这么做，
  我们不这么做反而引入无关变量）。结构上的直接好处：共享 `fc` 是一个随任务**增列**的
  `D→|已见类|` 矩阵，局部 CE 下旧类列的梯度恒为 0 → **旧类的投票参数天然冻结**，
  四个遗忘入口（2.10）里 `fc` 这个入口被掩码直接封掉一半（旧列不动，新列只学新类）。
- **一个部件投票特有的决策点**：CE 作用在 mean 之后的 `outputs`（IVPT 原样）还是逐部件
  独立算 CE？**保持 mean 之后**。理由：mean 后 CE 允许部件自由分工（某部件对某类投弱票，
  只要平均正确），逐部件 CE 则强迫每个部件独立可分类——对头/翅/身这种局部证据是过强
  要求（翅膀单独看常分不出近缘种）。**边界**：mean 后 CE 容许「部件搭便车」（一个部件
  干活、其余打酱油），这个风险不归 L1 管——L4 presence 防哑火、L5 orth 防同质化，
  分工明确。
- ⚠️ **遗留给 P5 的必答题**（3.3 已立案）：L1 的梯度经读出软分割图有一条通路进原型
  （IVPT 原样不切断）——「分类要不要被允许塑形原型」在 4.7 的梯度账本里看得最清楚，
  裁决归 P5。

## 4.2 L2 consistency —— 删：对象消失，且没人需要接它的班

- **IVPT 里管什么**：浅层聚合粗图向收尾干净图做 KL 看齐，本质是**路由的监督信号**
  （LD 损失 2 + FL Part 6.5：路由只由它学）。
- **删的理由**：3.6 已收账——学生（`m_buffer` 聚合粗图）没了，老师的「干净」也依赖
  层级读出设定，且 CIL 下老师自己随任务漂移（漂移链）。
- **谁接管「跨层一致」**：**没人，因为这个需求在新架构下降级了**。单套共享原型下，
  各注入层的软分割图是同一套原型对**不同深度特征**的响应——层间差异反映特征演化，
  是自然现象而非需要矫正的错误；读出与全部正则只作用在读出层那张图上，浅层图只是
  prompt 的中间产物，没有「必须跨层一致」的硬需求。
- **预编号扩展**（不是开放分支）：若实验发现浅层图混乱拖累 prompt 质量，对策是把
  L3/L8 **顺延作用到中间层的图**（C12 边界已留的「按需扩展」口），而不是恢复 KL 蒸馏
  ——前者只是扩大现有正则的作用面，后者要把老师/学生那套机制连根再造。

## 4.3 L3 tv —— 留：原样，且删 C5 后责任加重

- **IVPT 里管什么**：罚相邻 patch 跳变，本质=「边界总长×跳变高度」，逼部件成连通团块
  （LD 损失 3）。
- **CIL 下的理由**：无标签、单前向开销、作用在读出图——跨任务通用，照搬。
- **责任加重**：3.4 删掉 `p_bias` 后，「部件区域空间上不乱跳、不碎片化」的责任主要落
  在 tv（成块）+ L8（果断）上——tv 的权重是删 bias 风险预案的第一旋钮（3.4 ③）。
- **边界**：tv 偏好大块、平滑边界，对「小而关键」的部件（细喙、眼睛）有抹平倾向——
  权重往上调时要盯部件大小分布，不是免费旋钮。

## 4.4 L4 presence —— 留：防坍缩在增量下更重要，但作用范围有一个必须改的细节

- **IVPT 里管什么**：`avg_pool(3×3) → 空间 max → 跨 batch max → 1−均值`，逼每个前景
  部件至少在 batch 某处有一小片强响应，防退化哑火（LD 损失 4，body-C 的主要克星）。
- **CIL 下更重要**：新任务数据少而偏，新加入的原型冷启动最容易一个 patch 抢不到
  （2.6 边界）——presence 是新原型的「出生保障」。
- ⚠️ **必须改的细节（直接照搬会主动制造遗忘）**：presence 作用在「全部前景部件」上。
  增量下部件集合里有旧任务的部件，而**旧部件在新任务图像里可能本来就不存在**（新类
  未必有旧类的部件）。这时照搬 presence = 强逼旧原型在新图像上「必须找到自己」→
  旧原型被推着去抓不属于它的区域 → **正则亲手制造旧原型漂移**。这是把单数据集损失
  搬进 CIL 时最典型的隐性陷阱，必须显式处理：presence 的**作用范围限制在「当前任务
  正在训练的部件」**。「哪些部件算当前任务的」由 P5 的原型组织方式给出——若部件全任务
  共享（头/翅/身这种通用部件，新类图像也有），全体参与没问题；若逐任务新增，则只罚
  新增部件。这是 P5 决策的**连带条款**，两种形态的规则都已写死，不是留白。
- **跨 batch max 的语义在 CIL 下恰好合理**：「部件只要在 batch 里某张图出现过就算存在」
  ——天然容忍「这张图没有这个部件」，比逐图强制存在温和，照搬。

## 4.5 L5 orth —— 改(加强)：任务内原样 + 跨任务隔离的思想出口

- **IVPT 里管什么**：调制后部件特征两两余弦推向 0，防部件学成同一个东西（LD 损失 5，
  含「modulation 中心化导致负相关、orth 把负相关也推向 0」的细节）。
- **任务内**：原样保留，理由同 IVPT（防部件同质化），且它是 4.1 说的「搭便车」风险的
  第二道防线。
- **跨任务（加强的那半）**：orth 的思想——「不同语义单元在表征上互不重叠」——正好是
  CIL 干扰隔离的语言：新任务部件若与旧任务部件正交，softmax 竞争和投票两个层面都
  不容易互相侵蚀。**与 CODA-Prompt 的对照点**：CODA 对 prompt 分量做正交是**参数层面**
  的干扰隔离（分量不可视）；我们的正交作用在**部件语义层面**（每个被正交的单元有
  软分割图可看）——同源思想、不同层次，写论文时是现成的定位句。
- ⚠️ **一个欧氏竞争特有的细节（设计跨任务隔离时不能漏）**：softmax 竞争的输入是
  **负欧氏距离**，它不只看方向还看**范数**——FL Part 2.4 的现成证据：bg 原型范数小
  （`a_sq=1.077` vs 4.120），对谁都「不算太远」，天然有保底分。所以跨任务隔离若用
  「原型正交」实现，**必须连范数一起约束**（方向正交但范数失控，照样能在距离竞争里
  抢走别人的 patch）。实现落点（约束加在原型上还是特征上、冻结还是罚项）归 P5。
- **谁来接 IVPT 里它防坍缩的班**：没人需要接——任务内 orth 原样在岗。

## 4.6 L6 equiv —— 删：结构接管大半职责，剩下的买不起

- **IVPT 里管什么**：变换图再前向、反变换回来比余弦，逼部件随几何一致移动；8 个损失里
  唯一要**第二次完整前向**的（LD 损失 6）。
- **删的论证（两步）**：
  1. **职责被结构性接管**：`compute_xq` 是「同一原型对所有位置同样打分」的卷积式算子
     ——对**平移**天然等变；IVPT 里破坏等变性的头号元凶恰是被钉死的 `p_bias`（LD 损失 6
     的诚实标注原话：图转了、bias 不转）。**我们删了 C5，等变性的主要敌人已经不在了**
     ——平移等变由结构保证，不再需要损失去对抗自家的空间先验。
  2. **剩下的职责买不起**：旋转/尺度等变不被结构保证，靠 equiv 学的话要付**全程 ×2
     的训练前向**。CIL 的实验矩阵是「多任务 × 多数据集 × 多 seed × 还要陪跑 6 个
     baseline」，硕士课题的算力预算下这是真实约束；而旋转/尺度稳健性在 DINOv2 这种
     重增广自监督特征上已有相当底子（⚠️ 这半句是推断，不当论据用，只当风险评估）。
  - 结论：删。**留一个 eval-only 的钩子**：P7 的可解释性指标里加一项轻量等变性检查
    （评估时做一次变换前向，只算指标不进训练）——把「删了 equiv 部件还等不等变」从
    隐忧变成汇报数字。
- **谁接管**：平移部分由结构（删 C5 + compute_xq 形式）接管；旋转/尺度部分**明示不管**，
  靠 backbone 特征兜底并在 eval 指标里如实汇报。

## 4.7 L7 enforced_presence —— 留：背景原型是竞争的跨任务稳定锚

- **IVPT 里管什么**：bg 通道 avg_pool → 径向 mask（角=1 心=0）→ max → BCE 推向 1，
  权重 2.0 最重；和 presence 一对：前景有强峰、背景占边角（LD 损失 7）。
- **CIL 下的理由**，两条：
  1. 前景/背景分离是部件证据链可读的前提（部件图不能糊到背景上），照搬。
  2. ★ **CIL 下的新角色：竞争的稳定锚**。bg 原型全任务共享（「背景」概念跨类通用），
     而 FL Part 2.4 已经算过：bg 原型范数小、对谁都有保底分。这意味着**任何 patch
     永远有一个跨任务不变的去处**——新任务原型加入竞争时，背景区域的质量不容易被
     新原型乱抢（它们得先赢过 bg 的保底分），竞争分布的漂移被天然限幅。一个为单数据集
     设计的损失，在增量设定下白捡一份稳定性红利——这是「为何适用于 CIL」一类论证里
     最硬的一种（机制原生，非附加设计）。
- **边界**：径向 mask 内含「物体居中」假设。CIFAR-100/CUB 成立，ImageNet-R 的风格化
  图像（素描、卡通）背景定义模糊——该数据集上把权重从 2.0 降档是预编号的调参项，
  写进 P7 的超参表。

## 4.8 L8 pixel_entropy —— 留：管尖锐，但别指望它防漂移

- **IVPT 里管什么**：每个 patch 在部件通道上的分布熵推向 0，逼果断站队；与 tv 一横一纵
  （空间平滑 vs 通道尖锐）（LD 损失 8）。
- **CIL 下的理由**：便宜、作用在读出图；分割图干净是证据链能看的底线；且增量下有新角色
  ——新原型加入会在旧部件边界制造「分票犹豫」（正像 body-C 和 body-U 平分 0.488 那样），
  熵罚推动竞争尽快重新收敛到果断状态。
- **边界（防过度 claim）**：熵罚**只管尖锐、不管正确**——果断地归错也是低熵。它能让
  漂移后的图「看起来干净」，但不能阻止漂移本身；防漂移是 P5 机制的事，论文里不能把
  L8 写成防遗忘组件。

- **权重起点 = IVPT 默认**（各 1.0，enforced 2.0）。⚠️ 诚实：删了两条损失后配平**未必**

**梯度账本**（哪条损失的梯度能到达 2.10 的哪个入口；依据 FL Part 8 的 detach 布局：

# Part 5 —— CIL 适配的核心设计：部件词表的增量扩展与隔离

## 5.0 七个决定一览（先给全部结论，再逐个论证）

| # | 设计点（来自 1.5 清单） | 决定 |
|---|---|---|
| D1 | 原型组织方式 | **共享 1 个 bg 原型（任务 1 后冻结）+ 每任务新增一组前景部件原型，本任务训练、结束即冻结**——「部件词表」逐任务扩词、旧词不改 |
| D2 | 「cls→原型」第一案 | **保留通路（IVPT 原样），由冻结纪律使其无害化**：cls 只能塑形「正在自己任务里」的新原型，旧原型物理免疫 |
| D3 | 锚定初始化 | 新原型 = 新任务 patch 特征的 k-means 质心，**且与全体旧原型距离 < τ 的质心丢弃**（撞车即复用旧部件，不造重复词） |
| D4 | 竞争范围 | **全体竞争**（bg + 全部新旧组同台 softmax），配一条**欧氏分离损失 L_sep**（hinge margin）把新原型推离旧原型领地 |
| D5 | prompt 直通 | 每图只注入 **count_map 质量 top-k 的部件**的 prompt（k 固定）；投影 `p_norm/p_linear` 任务 1 训练后**冻结**；modulation 改**逐部件 LayerNorm([D])**（2.8 预案落地） |
| D6 | 投票头 | fc 增列 + 局部 CE（4.1）+ **★部件资历掩码**：类 c 只接受「c 训练时已存在的部件」的票 |
| D7 | 注入深度 | K=3（最后三个 block，IVPT 原设定），消融 {1,3,5}，与 baseline 注入深度对齐保公平 |

七个决定合起来要兑现的目标只有一句（0.4 主线）：**把「新任务能伤旧任务」压缩到一条
单一、可测、可解释的通道上**。5.7 收总账时给出这句的精确形态。

## 5.1 D1+D2：逐任务前景组 + 冻结纪律 —— 原型组织方式

- **为什么不是「全任务共享一套固定部件」**：通用部件假设在异构类上不成立——CIFAR-100
  里汽车没有翅膀，「头/翅/身」式的全局词表要么太抽象（部件失去语义可读性，证据链
  贬值），要么持续微调（原型漂移=旧图分割漂移，遗忘入口正面敞开）。共享方案把矛盾
  全压在「一套参数既要适应新类又不能动」上——这正是 CIL 文献反复证明走不通的形态。
- **决定**：每任务 t 新增一组 M 个前景原型（M≈5~8，超参），**只在任务 t 内可训，结束
  即冻结**。bg 原型全局唯一、任务 1 训练后冻结（它是 L7 的「竞争稳定锚」，锚必须不动）。
  整体形成一个**逐任务扩词、旧词只读的「部件词表」**。
- **D2 的裁决随冻结自然落地**：Part 3.3/4.9 立案的「cls 要不要被允许塑形原型」——
  答案是**保留 IVPT 原样的通路，但冻结纪律把它的作用域限制在「原型自己的任务内」**。
  保留的理由：纯无监督的部件未必可判别（翅膀形状可能恰是区分两个新类的关键，cls 梯度
  能把原型往判别性方向推，IVPT 自己就是这么训的）；无害的理由：旧原型冻结后，cls 这条
  通路物理上够不到它们——**不需要发明新机制，纪律本身就是裁决**。
- **与 prompt pool 的结构同构 + 语义换血**（论文定位句的素材）：「每任务一组、旧组
  冻结」与 L2P/DualPrompt 的 prompt pool 结构同构——但池里的元素从「不可视的参数地址」
  换成了「有软分割图、有池化特征、有投票记录的部件」。结构同构保证了工程与公平比较的
  可行性；语义换血是全部卖点。
- **边界**：组数随任务线性增长（T 组 × M 个）。10 任务 × 8 = 80 个前景原型，`compute_xq`
  是 `[B,N,D]×[B,D,HW]` 级运算，N=80 完全可负担；100 任务的长序列场景词表过大，**明示
  不在 claim 范围**（0.2 协议是 10 任务）。

## 5.2 D3：锚定初始化 —— 新词出生在空位上

- **规则**：任务 t 开始时，冻结 backbone 对任务 t 图像抽 patch 特征 → k-means 聚 M′ 个
  质心（M′ 略大于 M）→ **丢弃与任意旧原型（含 bg）欧氏距离 < τ 的质心** → 剩下的
  （≤M 个）作为新组初始化。
- **三个作用，一条规则全包**：
  1. **冷启动即有领地**（2.4 已论证）：质心与 `compute_xq` 同用欧氏度量，新原型第一步
     就能赢下自己簇内的 patch，不依赖已删的 `p_bias` 来分工——「分工」从空间切换成
     语义切的承诺（3.4 ③）在这里兑现。
  2. **不造重复词**：与旧原型撞车的质心被丢弃，意味着**那块语义由旧部件继续解释**——
     这就是「部件复用」：任务 5 的鸟头 patch 继续归任务 1 的「头」部件，旧部件为新类
     投票（fc 新列训练时旧部件在场，票权合法，见 5.5）。知识迁移以「词表复用」的形式
     发生，且每次复用都可视。
  3. **给 L_sep 一个好起点**：出生即远离旧原型，分离损失只需「维持」而非「拉开」，
     训练动力学温和。
- **边界**：τ 是新超参（丢弃阈值），太小→重复词、太大→新词不足。调参起点：τ 取旧原型
  两两距离分布的下分位数（数据驱动而非拍脑袋）；消融行：有/无丢弃规则。⚠️ k-means 在
  风格化数据（ImageNet-R）上质心质量未验证——预编号风险，落在 P7 的数据集风险表里。

## 5.3 D4：全体竞争 + 欧氏分离损失 —— 正面回答 0.4 的矛盾

- **为什么竞争必须全体**（而不是「新组只和 bg 竞争」之类的隔离竞争）：推理时没有任务
  id，软分割必然跑在全体原型上；若训练时只在子集内竞争，训练/推理的归一化分母不同，
  分割图系统性失真——所以竞争范围**没有真正的设计自由度，全体竞争是被推理设定逼出来
  的唯一选项**。设计自由度全在「怎么让全体竞争无害」。
- **训练侧（新任务图像）**：全体竞争反而有利——旧原型在分母里当「占位的释义者」，
  新原型只能去赢「旧词解释不好的 patch」（解释得好的，新原型得先比冻结的旧原型更近
  才能抢走）——竞争结构天然推着新词去填空位，与 D3 的出生规则同向。
- **风险侧（旧任务图像，训练时看不到）**：新原型可能在旧图上抢走本属旧部件的 patch
  ——这是 0.4 矛盾的残余形态，也是全方法**唯一不能被冻结纪律封死的通道**。两层限幅：
  1. **L_sep 欧氏分离损失**（L5 加强项的实现落点）：对每个新原型 q_new 与每个旧原型
     q_old，罚 `max(0, m − ‖q_new − q_old‖²)`（hinge，margin m）。**用欧氏距离而非
     余弦正交**，正是 4.5 那条范数警告的兑现：竞争看的是距离（方向+范数），隔离就该
     在距离上做——方向正交但范数失控照样抢 patch，欧氏 hinge 一并管住。
  2. **bg 保底分限幅**（4.7 白捡的红利）：旧图的背景区域有冻结 bg 原型的保底分护着，
     新原型可抢的地盘进一步缩小。
- **边界（诚实）**：限幅≠归零。「新原型在旧图上的抢夺量」是结构上无法消除、只能压低
  和**测量**的残余风险——它因此被指定为 P7 部件稳定性指标的核心观测对象，以及
  「有/无 L_sep」消融的主指标。方法的诚实形态是「把遗忘压进一条可测的窄缝」，
  不是「证明遗忘为零」。

## 5.4 D5：prompt 直通 —— 注入「检测到的证据」而非「检索到的参数」

- **通路**：注入层 l 上，软分割 + `compute_feat` 得到全部部件的池化特征与 `count_map`
  → 取 **count_map 质量 top-k** 的部件（k 固定，如 5）→ 各自过 `p_norm`/`p_linear`
  → k 个 prompt 拼回序列过 block。删掉的细→粗聚合由「top-k 选择」顶位——序列长度
  固定（不随词表增长），计算量与任务数解耦。
- **为什么 top-k 选「质量」**：count_map 质量 = 该部件在这张图上实际占据的软面积
  （FL Part 4.4）——「这张图里真实出现了哪些部件」的现成度量。于是注入的语义变成：
  **把图上检测到的 k 个最显著部件的描述喂回主干**。与 L2P 的对照从机制层就分开：
  L2P 检索「该用哪份参数」（query-key 匹配，匹配权重无图像语义），我们注入「图上有
  什么」（每个被注入的 prompt 都有软分割图作底）——**连 prompt 的选择行为本身都是
  可解释的**（哪些部件被注入、质量多少，逐图可查可画）。
- **投影冻结**：`p_norm`/`p_linear` 是「部件特征→prompt 空间」的通用翻译器，不携带
  类知识——任务 1 训练后冻结，封死 2.10 的投影入口。新任务的新部件照样通过冻结翻译器
  注入（翻译器翻的是「部件特征」这门语言，不是某个任务的方言）。⚠️ 「翻译器任务无关」
  是假设不是定理——预编号消融：投影冻结 vs 继续训练（后者若明显更好，说明假设破产，
  投影改为逐任务小组件并入 D1 的冻结纪律）。
- **modulation 落地**（2.8 预案拍板）：改逐部件 `LayerNorm([D])`——形状与词表大小
  解耦；每个部件的 LN 参数随该部件的组一起训练和冻结，归入 D1 纪律，不再单列。

## 5.5 D6：投票头 —— 部件资历掩码，让旧类的决策函数对扩词免疫

- **基础形态**（4.1 已定）：共享 `fc: D→|已见类|` 随任务增列，局部 CE 封旧列。
- **★资历掩码（本方法投票头的核心创新）**：发现问题——fc 旧列虽然冻结，但**新部件**
  也会过共享 fc 对旧类打分：`score(新部件, 旧类) = 新部件特征 · 冻结旧列`。旧列训练时
  这些部件还不存在，这笔票是**从未被训练过的噪声票**，却混进旧类 logit 的平均里——
  词表每扩一次，旧类的决策函数就被无声稀释一次。**修复：类 c 的 logit 只平均「c 的
  训练任务结束前已存在的部件」的票**：
  `logit(c) = mean_{k: 资历(k) ≤ task(c)} score(部件 k, c)`。
  - **效果是一个精确的不变性**：旧类 logit 的计算图与其训练时**逐项一致**（同一批部件、
    同一组冻结参数）——词表无论怎么增长，旧类的决策函数在代数上不变。
  - **新类不受限**：task(c)=t 的类接受全部 ≤t 的部件投票——旧部件合法地为新类作证
    （5.2 的复用故事在票面上兑现）。
  - 实现是一张 `[部件 × 类]` 的 0/1 掩码，无参数、无额外前向——「删繁就简」纪律下
    新增机制的样板：一行掩码买一条不变性。
- **校准**：默认**不加**额外校准头。理由：局部 CE + 资历掩码已把「旧类 logit 被系统性
  压低/稀释」的两个结构性来源封掉；先看裸结果。⚠️ 不同任务的新列在不同数据上训练，
  跨任务 logit 尺度漂移仍可能存在（CIL 已知现象）——预编号对策：cosine 归一化分类头
  （prompt 系常用、与共享 fc 兼容），仅在主实验出现明显任务偏置时启用并如实汇报。

## 5.6 D7：注入深度 K —— 沿用 + 对齐

- K=3（最后三个 block）：IVPT 原设定（FL Part 0.4），部件语义在深层特征上才稳定，
  浅层注入是给「还没看懂图」的特征喂部件、徒增成本。消融 {1, 3, 5}。
- 公平性条款：baseline 的 prompt 深度/长度设置（DualPrompt 的 e-prompt 层位、CODA 的
  prompt 长度）与我们的 K、k（top-k）在 P7 里放进同一张「可调预算对照表」，保证不是
  靠多塞 token 赢的。

## 5.7 防遗忘总账：四个入口逐个销账 + 方法的中心命题

回到 2.10 体检表的四个入口：

| 入口 | 处置 | 残余风险 |
|---|---|---|
| 共享 fc | 局部 CE 封旧列（4.1）+ 资历掩码封新部件噪声票（5.5） | 跨任务尺度漂移（预编号：cosine 头） |
| prompt 投影（+modulation） | 任务 1 后冻结（5.4）；逐部件 LN 归入组冻结 | 「翻译器任务无关」假设（预编号消融） |
| 原型本体 | 逐任务冻结（5.1），cls 通路作用域被纪律限死 | 无（物理冻结） |
| softmax 竞争范围 | 全体竞争不可避（5.3），L_sep + bg 锚双重限幅 | ★**唯一实质残余**：新原型在旧图上抢质量 |

于是整个方法收束为一个**中心命题**（论文的理论卖点，可写成 proposition）：

> **命题（解释保持 ⇒ 预测保持）**：在上述冻结纪律 + 资历掩码下，对任意旧任务图像，
> 若它的软分割结果（含 top-k 注入选择）在学习新任务后不变，则它在所有旧类上的 logit
> **逐位不变**。
>
> 理由：旧类 logit 的计算图中，除软分割外的一切——backbone、旧原型、投影、旧部件 LN、
> fc 旧列——全部冻结，其余算子（compute_xq/compute_feat/距离/池化）无参数；资历掩码
> 保证新部件不进旧类的票池。唯一活动自由度就是软分割本身。

这个命题做成了一件 baseline 都做不到的事：**把「遗忘」与「解释的漂移」在机制上焊死**
——遗忘不再是只能事后测精度的黑箱现象，它有了唯一的必经通道（旧图分割漂移），这条
通道可视（软分割图）、可量化（P7 稳定性指标）、可归因（哪个新部件抢了哪个旧部件的
哪块区域）。逆否形式同样有用：旧类 logit 变了 ⟹ 一定是分割漂了 ⟹ 去分割图里找凶手。
0.2 封口模板的二级 fallback（遗忘诊断）因此不是退路上另起炉灶，而是中心命题的直接应用。

⚠️ 命题的边界，自己先说破：① 它是**条件不变性**（"若分割不变"），不是无条件防遗忘
——分割漂移量就是方法的全部敞口，5.3 已指定其为核心观测对象；② top-k 选择是离散的，
临界处小漂移可能翻转选择导致 logit 跳变——k 取稍大、质量加软化（如质量比例阈值）是
预编号的工程缓冲；③ 命题对「旧类 logit」成立，新旧类之间的**相对**尺度（5.5 边界）
不在其覆盖内。

## 5.8 创新点清单（论文 contribution 形态）+ 与「删」的呼应

1. **部件词表式增量结构**（D1+D3）：逐任务扩词、旧词冻结、撞车即复用——prompt pool
   的结构、部件语义的内容，每个池元素可视。
2. **欧氏分离 + bg 锚的竞争限幅**（D4 + L7 红利）：对「全局 softmax 竞争 × 增量原型」
   这一本工作独有的矛盾给出的针对性设计。
3. **证据 top-k 注入**（D5）：prompt 选择从「参数检索」换成「部件检测」，选择行为
   本身可解释。
4. **部件资历掩码**（D6）：一行掩码换一条「旧类决策函数对词表增长不变」的代数保证。
5. **中心命题**（5.7）：解释保持 ⇒ 预测保持——可解释性与防遗忘的机制级焊接，
   以及由此而来的遗忘归因能力。

与 Part 3 的呼应收口：被删的层级机制群腾出的复杂度预算，恰好花在 1~4 这四件事上——
每一件都是「为何删、为何这样改、为何更适配 CIL」三问的同一份答案。

# Part 6 —— 与 8 个对比方法的逐一对照

## 6.0 对照的目的与读法

每个 baseline 三段：**机制**（一句话说准它怎么工作）→ **本质差异**（和我们的方法在哪个
轴上分开，不是泛泛的"我们可解释"）→ **公平条款**（比较时必须对齐什么，否则赢了也不算）。
⚠️ 各方法的机制描述基于其论文的通行理解，**落地前（P8）须对照 PILOT 实现逐一核对**
（PILOT 的复现细节有时与原文有出入，以实际跑的代码为准）。

通用公平条款（适用全部，先立在前）：同 backbone 同预训练权重、同任务划分与类顺序
（同 seed 集合）、同输入分辨率、无 exemplar（全员 rehearsal-free 设定）、可调参数量与
注入 token 预算放进同一张表汇报（D7 条款）。

## 6.1 L2P —— 同用「池」，检索地址 vs 检测证据

- **机制**：可学习 prompt 池 + 可学习 key；冻结 ViT 的 [CLS] 特征当 query，余弦匹配
  top-N 个 prompt 拼到输入序列；池全任务共享、持续训练。
- **本质差异**：两条。① **选择信号**：L2P 的 query-key 匹配是「图像整体特征 ↔ 参数
  地址」的检索，匹配权重没有图像内部结构的语义；我们的 top-k 注入由 count_map 驱动
  ——「图上检测到哪些部件」——选择本身携带空间证据（5.4）。② **池元素的训练制度**：
  L2P 的池全程可写（旧 prompt 持续被新任务更新，遗忘入口常开，靠检索稀疏性弱隔离）；
  我们的词表旧组物理冻结。可以说：**我们把 L2P 的「软隔离」（希望不同任务检索不同
  prompt）换成了「硬隔离 + 单一敞口」（5.7 总账）**。
- **公平条款**：L2P 默认 prompt 拼在输入层，我们注入在最后 K 层——注入位置是混淆变量，
  报告时把「注入层位 × token 数」列进预算表；L2P 的池大小 × top-N 与我们的词表 × top-k
  对齐到相近的激活参数量。

## 6.2 DualPrompt —— 任务推断 vs 无须推断

- **机制**：G-Prompt（全任务共享，浅层）+ E-Prompt（每任务专属，中层，prefix-tuning
  形式）；测试时用 query-key 匹配**推断任务身份**，选对应 E-Prompt。
- **本质差异**：DualPrompt 的预测质量上限被「任务推断准不准」卡住——推断错任务，
  挂错专家，整图特征都错。我们**结构上不存在任务推断这一步**：全体部件同台竞争，
  分类靠资历掩码后的全词表投票——没有「选错专家」这种失败模式，代价换成了 5.3 的
  竞争漂移敞口。这是两种增量结构的根本分野：**按任务路由参数 vs 按内容竞争语义单元**，
  论文里值得作为一对范式写。
- **公平条款**：E-Prompt 在 PILOT 里的层位设置（通常中段若干层）与我们 K=3 的层位
  不同——预算表里列明；其 G/E 拆分没有对应物，整体 token 预算对齐即可。

## 6.3 CODA-Prompt —— 最近的强敌：同用正交，参数空间 vs 语义空间

- **机制**：prompt = 一组「prompt 分量」的注意力加权和（权重由输入 query 对分量 key
  的注意力算出，端到端可微、无硬检索）；分量随任务增组，新分量对旧分量施加**正交
  约束**；旧分量冻结。
- **本质差异**：结构上和我们最像的 baseline——「每任务增组 + 旧组冻结 + 新旧正交」
  三件套全对得上。分野在**约束和组合发生的空间**：① CODA 的正交施加在 prompt 分量/
  key 上（参数空间，分量本身无图像语义，正交防的是权重干扰）；我们的 L_sep 施加在
  部件原型上（特征空间的欧氏分离，每个被分离的单元有软分割图，分离防的是 patch 抢夺
  ——且因竞争是欧氏的，用距离而非角度，4.5/5.3）。② CODA 的「组合」是注意力加权
  （连续混合，单个分量的贡献不可视）；我们的「组合」是 top-k 离散选择 + 部件投票
  （每一项贡献可单独读出）。**精度上 CODA 是 prompt 系里最该赢我们的对手；如果我们
  与它打平且给出证据链，主 claim 即成立**——0.2 把目标定为「不低于 CODA 2 个点」
  正是因此。
- **公平条款**：CODA 分量数随任务增长的 schedule 与我们 M（每任务原型数）对齐到相近
  总参数；其正交损失权重与我们 λ_sep 各自调到各自最优（约束强度不强行对等，各用
  各的最优是更严格的公平）。

## 6.4 CPP —— ⚠️ 术语撞车：它的「prototype」不是我们的「原型」

- **机制**：任务专属 prompt + 对比原型损失——「prototype」指**特征空间里的类中心**
  （每类一个/多个质心），训练用对比损失把特征拉向本类质心，推理用最近质心分类。
- **本质差异**：先排雷——**两个 "prototype" 是两个东西**：CPP 的原型是「类的特征
  质心」（分类器侧，无空间结构）；我们的原型是「部件的空间模板」（有软分割图、在
  patch 网格上竞争）。论文写作时必须显式区分（部件原型 vs 类质心），否则审稿人按
  CPP 那套理解我们，整个证据链故事就读歪了。实质差异：CPP 的解释能力止于「这张图的
  整体特征离哪个类中心近」；我们能说「图的哪块区域、哪个部件、给哪个类投了多少」。
- **公平条款**：CPP 不在 PILOT 里（0.2 已定：引用论文数字）。引用对比只在协议完全
  对齐的数据集行上做（同 backbone 同任务数），对不齐的行宁可不列——引数字最容易被
  挑的就是协议错位。

## 6.5 LAE —— 正交的轴：它管「怎么积累」，我们管「积累什么」

- **机制**：PET 模块无关的统一框架——online 模块学新任务，offline 模块用 EMA 慢速
  积累，推理时 online/offline 双路集成。插 prompt/adapter/LoRA 皆可。
- **本质差异**：LAE 回答的问题是「持续到来的参数更新怎么积累才稳」（EMA + 集成），
  与参数的语义无关；我们回答的是「增量参数应该长成什么语义形态」（部件词表）。
  两者几乎正交——理论上我们的部件组也能套 LAE 的 EMA 积累。但**不做这个组合**
  （0.2 封口纪律）：EMA 慢混会把冻结词表变成「缓慢漂移的词表」，5.7 中心命题的
  「逐位不变」立即失效——这是一个「组合反而毁掉卖点」的现成反例，写在论文讨论里
  比做实验更有价值。
- **公平条款**：LAE 在 PILOT 里默认的 PET 形态（prompt 版）参与对比；其双路前向的
  推理成本计入效率表。

## 6.6 Continual-CLIP —— 参考线，不是对手

- **机制**：冻结 CLIP，类名过文本编码器当分类器，零训练零增量参数。
- **本质差异**：它不是一个「方法」而是一条「预训练模型零样本能力」的水位线。backbone
  都不同（CLIP 双塔 vs 我们的视觉单塔），严格公平比较不存在。
- **公平条款**：按惯例列为**参考行**（标注 backbone 不同），不进主对比结论；它的价值
  是标定「不学习能拿多少分」，凡是低于它的训练方法都要解释为什么。

## 6.7 SLCA —— 另一个训练制度的代表 + 分类器校准的对照点

- **机制**：放弃冻结，全 backbone 以极小学习率慢调（slow learner），分类头正常学习率；
  任务结束后用各类特征统计（高斯采样）做分类器对齐（classifier alignment）矫正任务
  偏置。
- **本质差异**：训练制度上的对照组——「动 backbone 但动得很慢」vs 我们「绝不动
  backbone，动外挂词表」。另一个有用的对照维度：SLCA 的 classifier alignment 和我们的
  资历掩码都在治「分类器的任务偏置」，但前者是**事后统计矫正**（额外阶段、需存特征
  统计），后者是**结构性预防**（前向里的 0/1 掩码，5.5）——同病不同药，论文讨论
  分类器偏置时的现成对仗。
- **公平条款**：SLCA 动了 backbone，激活参数量与我们不同量级——在效率表里如实列出
  （它是「贵但强」的代表）；其结果用 PILOT 复现。

## 6.8 EASE —— 同用「每任务一组 + 冻结」，子空间集成 vs 词表竞争

- **机制**：每任务训练一个轻量 adapter 形成任务专属特征子空间，旧 adapter 冻结；推理
  时图像过**所有**任务的 adapter 取得多个子空间特征拼接，配原型式分类头；旧类在新
  子空间缺训练数据，用语义引导（类相似度）补全旧类原型。
- **本质差异**：增量纪律（每任务一组、旧组冻结）与我们相同，分野在**增量单元的组织**：
  EASE 的单元是「整图级特征子空间」，推理要过 T 个 adapter（前向成本随任务数线性涨）；
  我们的单元是「patch 级部件」，全词表在**一次**前向里竞争（原型数涨但都在同一次
  compute_xq 里，成本近常数，5.1 边界）。EASE 的「语义引导补旧类原型」和我们的「部件
  复用 + 资历掩码」解决同一问题（旧类在新增量单元下怎么办）——它靠类间相似度**估**，
  我们靠词表共享 + 票池冻结**保**。效率表 + 这组对仗是和 EASE 比较的两个落点。
- **公平条款**：EASE 的 adapter 总参数量与我们的词表 + 投影总量对齐；其随任务增长的
  推理 FLOPs 必须如实列出（这是我们占优的轴，但要用同一测量脚本）。

|---|---|---|---|---|---|---|
| L2P | 共享 prompt 池（可写） | query-key 检索 top-N | 检索稀疏性（软隔离） | 线性头+局部CE | 无（检索权重无空间语义） | 不需要 |
| DualPrompt | G 共享 + E 每任务 | 任务推断选 E | E 按任务隔离 | 线性头 | 无 | **需要** |
| CODA-Prompt | prompt 分量逐任务增组 | 注意力连续混合 | 旧分量冻结+参数正交 | 线性头 | 无（分量不可视） | 不需要 |
| CPP | 任务 prompt+类质心 | 任务 prompt | 对比损失锚定质心 | 最近类质心 | 无（整图级） | 弱需要 |
| LAE | online/offline 双模块 | 双路集成 | EMA 慢积累 | 线性头 | 无 | 不需要 |
| Continual-CLIP | 无 | 无 | 无（零训练） | 文本嵌入 | 无 | 不需要 |
| SLCA | 全 backbone（慢） | 无 | 小 lr+事后分类器对齐 | 线性头+对齐 | 无 | 不需要 |
| EASE | 每任务 adapter | 全 adapter 并行+拼接 | 旧组冻结+语义补全 | 原型式头 | 无 | 不需要 |
| **Ours** | **部件词表逐任务增组** | **count_map top-k（内容驱动、可视）** | **旧组冻结+欧氏分离+bg 锚+资历掩码** | **部件投票（共享 fc+掩码）** | **★软分割图+部件向量+逐部件票** | **不需要** |

读表的三个落点（论文叙事的骨架）：
1. **「单图证据链」一列只有我们非空**——这是 0.1 thesis 的表格化，主卖点一目了然。
2. **防遗忘机制一列我们不是异类**（冻结+正交/分离是 CODA/EASE 已验证的套路），说明
   精度可比的 claim 有结构基础——我们没有为了可解释性发明一套未经验证的防遗忘玄学。
3. **任务推断一列暴露 DualPrompt 的失败模式我们结构性免疫**，而和我们同为「不需要」
   的 CODA/EASE，分别在「组合可视性」「推理成本」两轴上被我们的设计分开。

**公平性条款汇总**（P7 直接继承）：同 backbone/预训练/分辨率/任务划分/seed；全员无
exemplar；「注入 token 预算表」（层位×token数×激活参数量）全员列出；CPP 与
Continual-CLIP 按 0.2 处理（引用行/参考行）；EASE/LAE/我们 的推理 FLOPs 用同一脚本测。

# Part 7 —— 实验方案

## 7.0 总则

- 实验只为验证 0.2 的主 claim 及其两级 fallback 服务，不为「多探索一下」加行。
- 凡是前文预编号过的消融/预案，本 Part 收拢成表并指回出处编号；没有出处的实验不加。
- 三条「怎么算成功」的纪律（执行阶段见 7.8）：每个阶段先写成功判据再跑；mental model
  与数字打架时五分钟内看数字；第一稿就 print 中间量。

## 7.1 backbone 决策（兑现 2.2 的遗留）

**主 backbone = ViT-B/16 DINOv2**，理由：部件机制的可行性依赖 DINOv2 特征的部件涌现性
（IVPT 的隐性前提，2.2），方法侧没有让步空间——所以让 baseline 来对齐我们：
**全部 6 个 PILOT baseline 在 DINOv2 上重跑**（PILOT 支持换 backbone）。

- ⚠️ 已知代价（2.2 边界）：DINOv2 上的 baseline 没有文献数字兜底，重跑结果无从校验
  「复现对不对」。两道保险：① 同时在 **IN21k-sup ViT-B/16** 上重跑 baseline 一遍，与
  PILOT 论文/各原文数字对表，先证明「我们的复现管线是对的」，再信 DINOv2 上的数字；
  ② 我们的方法也在 IN21k-sup 上跑一组（只主协议、不全套）——既当稳健性检查（部件
  机制离开 DINOv2 还成不成立），也让两个 backbone 的表互相印证。
- 预算意识：IN21k-sup 那一遍 baseline 可直接采用 PILOT 既有配置，调参成本≈0；真正的
  调参只发生在 DINOv2 主线上。

## 7.2 数据集与协议（0.2 锁定，此处只落细节）

| 数据集 | 角色 | 协议 | 备注 |
|---|---|---|---|
| CIFAR-100 | 标准主战场 | B0，10 任务 × 10 类 | 分辨率按 PILOT 惯例上采样到 224 |
| ImageNet-R | 分布偏移主战场 | 10 任务 × 20 类（200 类） | ⚠️ 双预案挂此：enforced 降权（4.7）、k-means 质心质量（5.2） |
| CUB-200 | 细粒度展示场 + 一级回退主场 | 10 任务 × 20 类 | 有 keypoint 标注，部件指标的唯一可标定场 |

- 全员 rehearsal-free、无 exemplar；3 个随机类顺序（seed 1993/1996/1997 取 PILOT 惯例），
  报均值±标准差。
- 公平条款全套继承 6.9：同 backbone/分辨率/任务划分/seed；token 预算表；CPP 引用行、
  Continual-CLIP 参考行；FLOPs 同脚本。

## 7.3 精度与效率指标

- **精度**：平均增量精度 Ā（每任务结束测一次已见类、求均值，CIL 标准主指标）+
  最终精度 A_T + 遗忘度 F（各类历史最好减最终）。
- **效率**：可学参数量 / 训练 FLOPs / **推理 FLOPs 随任务数的曲线**（vs EASE 的线性
  增长，6.8 指明的优势轴，必须画成图而不是单点）。

## 7.4 可解释性量化指标（★主 claim 的另一半，五项）

1. **部件分割稳定性 PSS（核心指标，5.3/5.7 指定）**：冻结一组各旧任务的 held-out 图像；
   每学完一个新任务，对每张旧图重算软分割，与「该图所属任务刚结束时」的分割比：
   - 硬版：per-patch argmax 一致率；软版：逐 patch 对称 KL；外加 top-k 注入选择的
     Jaccard（命题对它敏感，5.7 边界②）。
   - 随任务画成「**解释的遗忘曲线**」——本方法把遗忘压进的那条窄缝，就用这条曲线量宽。
2. **命题耦合验证（中心命题的实证）**：散点图，x=旧图的分割漂移量（PSS 软版），
   y=该图旧类 logit 的变化量。命题预言：y>0 的点必有 x>0（不存在「分割没动、logit
   动了」的象限）。这张图是 5.7 命题从「推导」变「实测」的一步，也是审稿人最好说服
   的呈现方式。
3. **部件语义质量 NMI/ARI（IVPT 同款，仅 CUB）**：用 keypoint 标注算部件发现质量
   （patch 归属 vs 真实部位的 NMI/ARI）；每个任务结束算一次自己任务的，全部结束后再
   回算全部——差值 = 部件语义退化量。与 IVPT 原文数字可粗对（静态上限参考）。
4. **等变性检查（4.6 的 eval-only 钩子）**：评估时变换图前向、反变换回来与原图分割比
   mIoU——验证「删 equiv 后等变性靠结构+特征兜得住」的论断，如实汇报。
5. **遗忘归因案例（账本的演示）**：取掉点最多的 3 个旧类，用 2.9 的加性账本拆解：
   count_map 漂移（定位坏）占比 vs score 切片漂移（投票坏）占比 + 配图。定性章节的
   骨架，也是二级回退的种子实验。

⚠️ 分寸声明（写论文时的措辞纪律）：CIFAR-100 的 32×32 上采样图像上「部件」未必有
CUB 那种解剖学语义——CIFAR/IN-R 上证据链的措辞用「区域级证据」，只有 CUB 上才说
「部件」。卖点不缩水（证据链机制相同），但不替数据集吹它给不了的语义。

## 7.8 执行阶段（granular：每阶段先写「怎么算成功」）

- **阶段 1：静态 sanity（单任务=简化版 IVPT）**。在 CUB 全量（不切任务）上训练简化
  主干，**成功判据**：NMI/ARI 不低于 IVPT 原文同设定的 ~80%；软分割图目检成块、
  部件可命名。这一步同时就是课题规划里「静态部件」工作的地基——失败则问题在简化
  本身（回 Part 3 检讨删减），与增量无关，问题定位干净。
- **阶段 2：最小增量 demo（2 任务）**。CUB 前 20+20 类，**成功判据**：① 冻结纪律的
  单元测试——学完任务 2 后，人为把任务 2 词表从竞争中摘除，旧图 logit 应与任务 1
  结束时**逐位相等**（中心命题的机制检查，桩级验证）；② 不摘除时 PSS ≥ 0.9（经验
  起点，跑了再校准）；③ 任务 1 的 A 降幅 < 3 点。
- **阶段 3：全协议**。三数据集 × 三 seed × 7 方法 + 消融 A1~A5；A6~A9 视预算排后。
  **成功判据 = 0.2 主 claim 原文**。

> 阶段 1/2 不达标就不进阶段 3——这是把「fallback 在早期就能触发」做进流程，避免
> 全协议跑完才发现地基有问题。
